# 专家批注的沉淀机制

## 批注渠道

专家在钉钉文档中直接修订或添加评论。工具读取评论用 `dws doc +review --node <URL>`；修订通过对比 AI 原稿与当前版本（`dws doc +fetch`）得到。

建议专家在评论开头加标签，方便自动分类（不加也可以，由 AI 判断）：
- `#模板`：这类操作的标准写法应该改
- `#规则`：通用写法规范
- `#个案`：只适用于这个产品，不要推广
- `#错误`：AI 抄错或理解错

## 分类与去向

| 类型 | 去向 | 例子 |
|---|---|---|
| 模板修订 | 单元操作库对应操作类型的模板，版本 +1 | 投料段落应增加"确认设备清洁状态" |
| 规则 | MOR 编写规则表，新增（试用） | 温度范围一律写成"55–65 ℃"，不写"60±5 ℃" |
| 解析错误 | 解析规则（process-schema 抽取规则），或补充触发词 | "charge" 未识别为投料 |
| 主数据缺失 | 设备库 / 物料库 | 缺少 R-305 的容积 |
| 个案 | 只记录在该产品备注，不推广 | 该产品需避光操作 |
| 偏好/表述 | 规则（试用），累计 3 次同类修改后转为生效 | — |

## 生命周期

- 新规则状态为**试用**；在之后 3 份 MOR 中被应用且未被修改的，转为**生效**。
- 模板修改必须经提出批注以外的另一位专家确认（四眼原则），再升级版本。
- 每次学习输出摘要：

```markdown
### MOR 学习摘要：{文档} {日期}
- 批注 {n} 条：模板 {n} / 规则 {n} / 解析 {n} / 主数据 {n} / 个案 {n}
- 模板更新：投料 v1.2 → v1.3（新增：确认设备清洁状态）
- 新规则（试用）：……
- 待专家确认：……
```

## 指标（每份 MOR 记录一行）

| 指标 | 说明 |
|---|---|
| 编写总工时 | 从开始到提交审核 |
| 专家修改条数 | 按类型分别统计 |
| 核对报告错误数 | 生成后、修改前 |
| 审核返工次数 | 提交审核后被退回的次数 |
| `[AI]` 段落采纳率 | 未修改或仅小改的比例 |

关注趋势：专家修改条数持续下降，说明模板和规则在收敛。
