## 建议上线顺序

1. 第 1 周：建企业上下文库，用纪要 skill 冷启动（术语、项目、人员）。
2. 第 2 周：上线约会和速读两个 skill，它们直接复用人员表和项目卡片。
3. 同步启动 MOR 的阶段 0（基线测量 + QA 确认 + 收集资料）。

## 智能约会：已确认流程

1. 根据会议主题和基础名单推荐参会人（依据人员表的职责领域、项目卡片），用户确认。
2. 用 `dws calendar busy search` 查询全部参会人在指定时间段的忙闲。**这只作为初步判断**，用来生成和排序候选时段。
3. **给每一位参会人发送选项式确认消息**，无论其日历显示忙或闲。消息包含：
   - 候选时段编号，例如"1. 周三 14:00–15:00"；
   - 对日历显示忙碌的时段，附一句"日历显示您此时段有安排，如可调整，仍可选择该时段"；
   - 回复方式：回复编号（可多选），或回复"都不行 + 可行时间"。
4. 用 `dws event +listen-im --kind sender` 监听每个人的回复；到截止时间前对未回复者提醒一次。
5. 全部回复或超时后汇总：**以本人回复为准，日历仅用于未回复者的推测**，并标注"未确认"。
6. 输出推荐时段、每个时段的可参加 / 不能参加 / 未确认名单，用户确认后创建日程并发送邀请。
