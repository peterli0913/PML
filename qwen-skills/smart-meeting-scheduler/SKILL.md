# 智能约会（smart-meeting-scheduler）

## 原则

- **日历只做初判，本人回复为准。** 每位参会人都要发送确认消息，不论日历显示忙或闲。
- **两个确认点必须停下来等用户**：参会人名单确认、最终时段确认。其余步骤自动推进。
- **发消息、建日程属于写操作**：只在对应确认点之后执行，不得提前发送。
- 任务状态写入"约会任务"表（结构见 `references/task-table.md`），会话中断后可以凭任务编号继续。

## 流程

### Step 1 理解需求
从用户输入中提取：会议主题、关联项目、基础名单、时间范围（例如"下周二到周四下午"）、时长（默认 60 分钟）、线上或线下、回复截止时间（默认发出后 4 个工作小时，且不晚于最早候选时段前 1 天）。缺项时一次性问清；时间范围必须有，其他项可用默认值。

### Step 2 推荐参会人（确认点 ①）
读取企业上下文库：
- 项目卡片：负责人、参与人员；
- 人员表：负责事项、决策权限、与我的关系；
- 决议记录：近期针对该项目的决策人；
- 未关闭行动项：与本议题相关的负责人。

库里信息不足时，用 `dws aisearch person --query "<议题关键词>" --dimension duty --format json` 补充候选。

输出分三档，每人一句理由：

```markdown
**必须参加**（缺席则改期）：张三 — 项目负责人；李四 — 需拍板放行策略
**建议参加**：王五 — 负责 QC 方法验证
**可选/知会**：赵六 — 仓库对接，会后同步纪要即可
**建议移除**（基础名单中与议题关联弱）：……
```

等待用户确认或调整名单，以及"必须参加"的划分。

### Step 3 日历初判
1. 用 `dws contact +lookup` 或人员表的 `userId` 解析全部参会人。
2. `dws calendar busy search --users <ids> --start "<ISO>" --end "<ISO>" --format json`。
3. 生成候选时段：在时间范围内，按时长切片（整点或半点开始），避开 12:00–13:30 和 18:00 以后（用户指定的除外）。
4. 按 `references/slot-scoring.md` 打分，取 **3–4 个**候选时段，必须参加者日历空闲多的排在前面。

### Step 4 逐人发送确认消息
- 按 `references/message-templates.md` 为**每个人**单独生成消息。该人日历显示忙的时段，加一句提示。
- 发送：`dws chat +dm --to "<姓名>" --content "<消息>"`。同名多候选时改用 `userId`，不要猜测。
- 记录每条消息的发送时间，把任务写入约会任务表（状态"等待回复"）。
- 向用户报告：已发送 N 人，截止时间是什么时候。

### Step 5 收集回复
两种方式，按运行环境选用：

**A. 实时监听**（会话可以持续运行时）
- 每人一个监听：`dws event +listen-im --kind sender --user-query "<姓名>" --events message --duration <到截止时间的分钟数>m`。参会人超过 8 人时，征得用户同意后改用 `--kind all-direct`，再在本地按参会人过滤。
- 必须等输出 `[event] ready` 后才算监听开始。
- 截止或全部回复后，按 `dws event status` 列出的订阅逐个停止：先 `dws event stop <subscribe_id> --dry-run`，确认后加 `--yes`。

**B. 回查**（会话不能常驻，用户之后说"看看约会回复"时）
- 对每个未回复的人：`dws chat +chat-messages --sender-query "<姓名>" --start "<发送时间>" --format json`，读取发送之后的单聊回复。

**解析回复**：
- 编号回复（例如"1、3"）直接映射到候选时段。
- 自由文本（例如"周三下午都不行，周四上午可以"）：映射到候选时段，并记录对方提出的新时段。
- 无法确定含义：**追问一次**（"想确认一下，您是指 X 吗？"），之后不再追问。
- 截止前 1 小时，对未回复者提醒一次：`dws chat +dm`，提醒文案见模板。

### Step 6 汇总推荐（确认点 ②）
以本人回复为准；未回复者用日历初判，并标"未确认"。按 `references/slot-scoring.md` 重新打分，输出：

```markdown
### 推荐时段
**首选：11-12（周三）14:00–15:00**
- 可参加（6）：张三、李四……
- 不能参加（1）：王五（建议参加；原因：出差）
- 未确认（1）：赵六（日历显示空闲）
**备选：11-13（周四）10:00–11:00** — 可参加 5，不能 2（含必须参加者李四）

### 提示
- 必须参加者全部可行的时段：只有首选
- 有人提出的新时段：钱七提议 11-14 上午（其他人未覆盖，未纳入）
```

所有候选时段都有必须参加者缺席时，明确告诉用户，并给出两个选项：在新的时间范围内再约一轮，或者按缺席最少的时段开会。

等待用户选定时段，并确认是否需要会议室、视频会议。

### Step 7 创建日程
- 需要会议室时：先 `dws calendar room search --start ... --end ... --format json` 拿到 `roomId`。
- 创建：`dws calendar event create --title "<主题>" --start "<ISO>" --end "<ISO>" --attendees <userIds> [--rooms <roomId>] --desc "<议程/背景>" --format json`。
- 回读：`dws calendar event get --id <eventId> --format json`，核对时间和参会人。
- 给"不能参加"的人单独发一句：会议已定在 X，会后同步纪要。
- 约会任务表状态改为"已建日程"，写入 eventId；会议索引表预建一条记录，关联项目和参会人。
