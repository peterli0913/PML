# 企业上下文库（钉钉 AI 表格）

一个 Base：**企业上下文库**。这个库由会议纪要、约会助手、文件分析、MOR 工具共用。
表之间用关联字段（`bidirectionalLink`）互相连接，构成轻量知识图谱：项目 ↔ 人员 ↔ 会议 ↔ 决议 ↔ 行动项。

## 表结构

标"🔗"的是关联字段，其余字段在第一步按 `text` 创建。

### 1. 术语纠错
| 字段 | 说明 |
|---|---|
| 错误写法 | 转写中常见的错写，可多个，用 `;` 分隔 |
| 正确写法 | 标准名 |
| 类型 | 项目 / 人名 / 基地 / 设备 / 物料 / 方法 / 部门 / 缩写 |
| 释义 | 一句话说明，帮助模型理解上下文 |
| 状态 | 候选 / 已确认 |

### 2. 项目卡片
| 字段 | 说明 |
|---|---|
| 项目名称 | 标准名或代号 |
| 别名 | 会上的各种叫法，用 `;` 分隔 |
| 类型 | 客户项目 / 内部改进 / IT系统 / 基建 / 管理 |
| 🔗 负责人 | → 人员（单选） |
| 当前阶段 | 例如：方案讨论、试点、上线 |
| 关键背景 | 3–5 句：为什么做、目标、硬约束 |
| 🔗 关联项目 | → 项目卡片（上下游、依赖） |
| 最近进展 | 由纪要回写，保留最近 3 条，格式为"日期：进展" |

### 3. 人员
| 字段 | 说明 |
|---|---|
| 姓名 | 通讯录标准姓名 |
| userId | 钉钉 userId，用于发消息和查日历；同名时以此区分 |
| 称呼 | 会上的叫法，用 `;` 分隔，例如"陈总;老陈" |
| 部门 | 来自通讯录 |
| 职位 | 来自通讯录 |
| 与我的关系 | 上级 / 下属 / 同部门同事 / 跨部门协作 / 外部（客户、供应商）；可附一句说明 |
| 负责事项 | 1–3 句：分管什么、对接什么、常拍板什么 |
| 决策权限 | 可拍板的事项范围，用于判断"已决/待决" |
| 🔗 常参与项目 | → 项目卡片（多选） |
| 信息来源 | 通讯录 / 聊天记录推断 / 会议推断 / 用户确认，可多个 |
| 置信度 | 已确认 / 推断 |
| 最近更新 | 日期 |

### 4. 决议记录
| 字段 | 说明 |
|---|---|
| 决议内容 | 一句话 |
| 🔗 关联项目 | → 项目卡片 |
| 🔗 来源会议 | → 会议索引 |
| 🔗 决策人 | → 人员 |
| 日期 | |
| 状态 | 有效 / 被替代 / 已撤销 |
| 🔗 替代为 | → 决议记录（单选） |

### 5. 行动项
| 字段 | 说明 |
|---|---|
| 事项 | 动词开头 |
| 🔗 负责人 | → 人员 |
| 截止 | 日期或"未明确" |
| 交付物 | |
| 🔗 关联项目 | → 项目卡片 |
| 🔗 来源会议 | → 会议索引 |
| 状态 | 未开始 / 进行中 / 完成 / 逾期 |

### 6. 会议索引
会议主题 / 日期 / 会议类型（项目推进 / 方案评审 / 决策会 / 例会 / 供应商交流）/ 🔗 参会人（→ 人员）/ 🔗 关联项目（→ 项目卡片）/ 听记链接 / 纪要链接。

### 7. 学习规则
规则 / 类别（重点判定 / 噪音 / 术语 / 格式 / 表述）/ 适用会议类型 / 来源会议 / 状态（试用 / 生效 / 废弃）/ 命中次数 / 被推翻次数。

### 8. 样例库
会议类型 / AI稿 / 人工终稿 / 修改要点 / 是否示范（每个会议类型最多保留 3 条示范）。

## 建库命令

### 第一步：建表和普通字段

```bash
dws aitable +base-bootstrap --name "企业上下文库" --tables '[
 {"name":"术语纠错","fields":[{"fieldName":"错误写法","type":"text"},{"fieldName":"正确写法","type":"text"},{"fieldName":"类型","type":"text"},{"fieldName":"释义","type":"text"},{"fieldName":"状态","type":"text"}]},
 {"name":"项目卡片","fields":[{"fieldName":"项目名称","type":"text"},{"fieldName":"别名","type":"text"},{"fieldName":"类型","type":"text"},{"fieldName":"当前阶段","type":"text"},{"fieldName":"关键背景","type":"text"},{"fieldName":"最近进展","type":"text"}]},
 {"name":"人员","fields":[{"fieldName":"姓名","type":"text"},{"fieldName":"userId","type":"text"},{"fieldName":"称呼","type":"text"},{"fieldName":"部门","type":"text"},{"fieldName":"职位","type":"text"},{"fieldName":"与我的关系","type":"text"},{"fieldName":"负责事项","type":"text"},{"fieldName":"决策权限","type":"text"},{"fieldName":"信息来源","type":"text"},{"fieldName":"置信度","type":"text"},{"fieldName":"最近更新","type":"text"}]},
 {"name":"决议记录","fields":[{"fieldName":"决议内容","type":"text"},{"fieldName":"日期","type":"text"},{"fieldName":"状态","type":"text"}]},
 {"name":"行动项","fields":[{"fieldName":"事项","type":"text"},{"fieldName":"截止","type":"text"},{"fieldName":"交付物","type":"text"},{"fieldName":"状态","type":"text"}]},
 {"name":"会议索引","fields":[{"fieldName":"会议主题","type":"text"},{"fieldName":"日期","type":"text"},{"fieldName":"会议类型","type":"text"},{"fieldName":"听记链接","type":"text"},{"fieldName":"纪要链接","type":"text"}]},
 {"name":"学习规则","fields":[{"fieldName":"规则","type":"text"},{"fieldName":"类别","type":"text"},{"fieldName":"适用会议类型","type":"text"},{"fieldName":"来源会议","type":"text"},{"fieldName":"状态","type":"text"},{"fieldName":"命中次数","type":"text"},{"fieldName":"被推翻次数","type":"text"}]},
 {"name":"样例库","fields":[{"fieldName":"会议类型","type":"text"},{"fieldName":"AI稿","type":"text"},{"fieldName":"人工终稿","type":"text"},{"fieldName":"修改要点","type":"text"},{"fieldName":"是否示范","type":"text"}]}
]'
```

建完后用 `dws aitable +list-tables --base <BASE_ID>` 取各表的 tableId。

### 第二步：建关联字段

`bidirectionalLink` 创建后，系统会**自动在被关联表生成反向字段**，所以每对关系只在一侧创建一次，不要两侧都建。

| 在哪张表建 | 字段名 | 关联到 | multiple | 自动生成的反向字段（在对方表） |
|---|---|---|---|---|
| 项目卡片 | 负责人 | 人员 | false | 人员 → 负责的项目 |
| 人员 | 常参与项目 | 项目卡片 | true | 项目卡片 → 参与人员 |
| 决议记录 | 关联项目 | 项目卡片 | true | 项目卡片 → 决议 |
| 决议记录 | 决策人 | 人员 | true | 人员 → 做出的决议 |
| 决议记录 | 来源会议 | 会议索引 | false | 会议索引 → 决议 |
| 行动项 | 负责人 | 人员 | true | 人员 → 行动项 |
| 行动项 | 关联项目 | 项目卡片 | true | 项目卡片 → 行动项 |
| 行动项 | 来源会议 | 会议索引 | false | 会议索引 → 行动项 |
| 会议索引 | 参会人 | 人员 | true | 人员 → 参加的会议 |
| 会议索引 | 关联项目 | 项目卡片 | true | 项目卡片 → 会议 |

"项目卡片.关联项目"和"决议记录.替代为"是同表自关联，改用 `unidirectionalLink`，避免生成重复的反向字段。

命令格式（每行一个字段）：

```bash
dws aitable field create --base-id <BASE_ID> --table-id <行动项tableId> \
  --name "负责人" --type bidirectionalLink \
  --config '{"linkedTableId":"<人员tableId>","multiple":true}' --format json
```

建完后用 `dws aitable field list --base-id <BASE_ID> --table-id <T>` 核对字段和反向字段是否齐全。

### 写入关联值

关联字段写入的值是对象 `{"linkedRecordIds":["<recordId>", ...]}`，所以写入前要先查到或新建目标记录，拿到 recordId。

## 读取策略（控制上下文长度）

- 术语纠错：全量读取（通常少于 300 条）。
- 人员：参会人，加上逐字稿中出现的姓名或称呼命中的记录。
- 项目卡片：只读与逐字稿关键词命中的卡片，最多 5 张。
- 决议和行动项：只读命中项目的有效决议，以及未关闭的行动项。
- 规则：读"生效"和"试用"状态；规则超过 40 条时，按会议类型过滤。
- 样例：按会议类型取 1–2 条示范。

## 记忆更新块格式

每次出完纪要后输出这个块，经用户确认后写入。

```markdown
### 记忆更新（待确认）
**会议索引**：{主题} | {日期} | {类型} | {参会人} | {关联项目}
**新增决议**：
- {决议} | {项目} | {决策人} | 状态=有效
- 变更：{旧决议} → 状态=被替代，替代为 {新决议}
**新增行动项**：
- {事项} | {负责人} | {截止} | {交付物} | {项目}
**已完成行动项**（会上确认完成的旧事项）：{事项} → 完成
**项目卡片·最近进展**：
- {项目}：{日期}：{一句话进展}
**人员新增/更新**：
- {姓名} | {职位/部门} | 称呼+={新称呼} | 负责事项={…} | 与我的关系={…} | 来源={…} | 置信度=推断
**术语候选**：{原词} → {推测正确写法}（{类型}）
```

## 冷启动（第一周）

1. 用户提供 5–10 份历史逐字稿和对应的人工纪要（如果有）。
2. skill 批量提取：
   - 高频专有名词及疑似误识别 → 术语候选；
   - 反复出现的项目或系统 → 项目卡片草稿；
   - 出现的姓名和称呼 → 按 `person-resolution.md` 解析，生成人员候选。
3. 先执行一次 `dws contact +me`，再列出用户的上级和直属下属，作为"与我的关系"的基准写入人员表。
4. 用户花约 1 小时确认，作为第一版库；先覆盖最常开会的 20–30 个项目、50–100 个术语，以及常见的 30–50 位同事。
5. 之后每次出纪要会自动补充候选，库会随使用逐步完善。
