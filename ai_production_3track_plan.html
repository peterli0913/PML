PART 01 · 上级要求与总体定位

不追求两年“全面智能化”，追求“有成效的可验证进展”

上层已明确：即使按 2–3 年周期推进，也必须在 AI 事业上形成较有成效的进展。落地口径应收敛为： 选对场景 → 打通底座 → 跑通闭环 → 形成可复制能力，而不是同时铺开过多方向。

3
领导圈定主线
视频巡检 / 技转辅助 / 生产预测指导。其他方向（报告起草、培训视频等）可作为共用底座的旁路收益，不抢主线资源。
1
共用底座优先
三条主线共享数据中间层、主数据、客户隔离与 AI 平台。底座不立，主线各自重建，投入会翻倍。
2–3年
成效验收窗口
Y1 出试点闭环与可演示成果；Y2 出可复制能力与运营机制；Y3 形成规模化覆盖与组织能力沉淀。

PART 02 · 整体思路

“底座先行 + 三线并行 + 波次验收”，用机制保证 2–3 年不断档

不要把三条主线拆成三个互不相关的供应商项目。正确打法是： 先立“基础设施与数据底座”为 0 号工程，再按主线成熟度分波次推进；每 90 天有可验收节点，避免“两年后才知道有没有用”。

推进逻辑（为什么这样排）

  • ① 视频巡检：硬件基础相对现成（CCTV），但组织/合规风险最大 → 先沟通后技术，适合做“可见闭环”。
  • ③ 生产预测：可继承 DH1 PdM、IP.21/DCS/LIMS 基础 → 适合做“可量化业务价值”。
  • ② 技转辅助：价值大但前置知识工程重 → 必须先结构化再模型，按 IP 资产建设推进。

三条不可破的纪律

  • 共用底座：批号 / 项目 / 设备 / 客户隔离一次建好，三线复用。
  • 场景收敛：每条主线 PoC 只做一个“最小可验收闭环”，禁止一上来全覆盖。
  • 人在环路：告警必有确认；技转建议必有资深签字；预测建议必有班组采纳/拒绝记录。

PART 03 · 三条主线边界与实操定义

先把“做什么 / 不做什么”钉死，避免项目膨胀

TRACK 01

视频巡检

要做：关键操作区 CCTV 流 → 边缘推理 → 违规/缺失动作告警 → 巡检员确认 → 培训反馈。

不做：PoC 不做实名识别、不做精细手部微操作、不做“AI 替代巡检员”对外表述。
TRACK 02

技转辅助

要做：历史项目结构化 → RAG 检索同类经验 → 放大风险矩阵初稿 → Aspen/CFD 机理叠加 → 资深签字。

不做：不做新化学反应发明；不做无资深复核的自动放行；客户间不共享具体 CPP/CQA 数值。
TRACK 03

生产预测指导

要做：用生产/质检/设备数据预测质量风险、设备健康、关键参数漂移，并输出可执行建议（维护窗口、取样加严、参数回调）。

不做：不做无解释的黑盒自动改 DCS 设定；不做跨客户数据混训导致泄密。

每条主线的“最小可验收闭环”（MVP）

主线输入系统动作人的动作验收口径（建议）
① 视频巡检 1 车间关键点位视频流 + 5 个 SOP 动作字典 实时识别缺失/违规 → 告警工单 巡检员 15 分钟内确认真/误报 误报率 ≤10%；告警闭环率 ≥90%；员工沟通无重大阻力
② 技转辅助 3 类主力反应 × 历史项目包 + 设备能力库 相似案例检索 + 风险矩阵初稿 资深工程师复核签字 结构化项目 ≥20；检索命中可用；初稿一次可用率 ≥60%
③ 生产预测 选定单元：IP.21/DCS + LIMS/EBR +（可选）振动传感 质量/健康分数 + 提前量预警 + 建议动作 班组长采纳/拒绝并回填结果 提前预警有效率可复盘；建议采纳有记录；无自动写设定值

注：验收阈值可按试点车间再校准；上表用于立项与阶段门禁，避免“做了很多功能却无法证明有用”。

PART 04 · 需要打通的数据底座

三条主线共用一层“可查询、可隔离、可追溯”的数据中间层

底座不是“再建一个大湖”，而是把业务真正要用的系统数据按主数据对齐、按客户隔离、按批号可追溯地接出来。 建议作为独立 0 号项目由 IT 主责、业务配合。

B1
系统取数层
IP.21 / DCS / MES·EBR / LIMS / QMS / EAM / SAP / CCTV
B2
主数据对齐
批号 · 项目号 · 设备号 · 物料 · 人员岗位 · 客户编码
B3
客户隔离
租户/权限/脱敏规则；只学规律不泄参数
B4
AI 平台层
特征库 · 模型注册 · 推理服务 · 审计日志

主线 × 数据源依赖矩阵（打通优先级）

数据源 ① 视频巡检 ② 技转辅助 ③ 生产预测 建议优先级 典型字段/对象
CCTV / NVR 必须 可选 — P0 点位、时间戳、区域、录像索引（边缘侧）
IP.21 / DCS / SCADA — 重要 必须 P0 T/P/流量/搅拌/设定值/报警；秒~分钟级
MES / EBR 重要 必须 必须 P0 批号、步骤、偏差、投料、人员、设备占用
LIMS / QC — 重要 必须 P0 CQA、中间体结果、放行状态、取样时间
QMS / 偏差 / CAPA 重要 重要 重要 P1 偏差类型、根因、纠正措施、复发标记
EAM / CMMS — 可选 必须 P1 工单、故障码、备件、维护历史、验证状态
工艺/技转文档库 SOP 动作 必须 重要 P0（技转） TPP/CPP、放大报告、风险评审、设备能力、会议纪要
SAP / 计划 — 可选 重要 P2 订单、交期、物料批次、成本（指导生产用）

必须先完成的 6 项数据治理

  • 统一批号 / 项目号 / 设备号映射表（跨系统 Join 的钥匙）
  • 明确客户隔离策略（权限、脱敏、训练语料边界）
  • 定义黄金时段对齐（工艺事件时间 vs 质检时间 vs 设备时间）
  • 建立标签字典（动作类、故障类、偏差类、反应类型）
  • 规定留存与审计（视频、模型输入输出、人工确认）
  • 输出字段级数据目录（谁拥有、谁可写、刷新频率、质量责任人）

实操建议：前 8 周只做“能支撑试点”的底座

  • 不要等“全公司数据湖”建成再开主线。
  • 按试点对象倒推：① 只要点位流+动作标签；② 只要选定反应的历史包；③ 只要选定单元的时序+质检。
  • 先打通 80% 高频字段，剩余 20% 允许人工补录并标记来源。
  • 每周发布一次“数据就绪度看板”（绿/黄/红）。

硬件补短板、软件建闭环；优先边缘与可审计，不上“黑盒上云”

类别建设内容备注

推荐技术路线（务实版）

① 视频巡检

  • PoC：优先兼容现有 CCTV 生态的成熟方案做通
  • 边缘推理 + 本地短视频存证
  • Pilot 阶段评估开源/自研降本可行性
  • 与巡检 SOP、培训系统打通

② 技转辅助

  • 核心知识库与引擎应归属凯莱英 IP
  • OCR/LLM 半自动结构化 + 人工校验
  • RAG 检索 + 机理模型（Aspen/CFD）叠加
  • 可引入短期方法论咨询，但不绑定数据

③ 生产预测

  • 时序/多变量模型 + 可解释特征
  • 质量预测与设备 PdM 分模块，同一底座
  • 输出“建议动作卡”，禁止直连改设定
  • 与班前会/维护计划/取样策略联动
合规硬约束：视频与客户工艺相关影像本地处理；模型训练语料分级；所有 AI 输出保留输入摘要、版本号、人工确认结果，满足审计抽查。

PART 06 · 统筹推动需要的专业人员与知识

不是“招几个算法就行”，而是业务+数据+AI+合规的联合编制

建议按“核心小队常驻 + 业务专家兼职承诺 + 外部能力按阶段采购”组织。人员不到位，再好的方案也会停在 PPT。

必须补齐的组织知识（培训包）

  • 业务侧：如何写标签、如何确认告警、如何拒绝/采纳建议
  • IT 侧：OT 数据时序对齐、客户隔离实现、模型审计
  • QA 侧：AI 辅助在验证/变更/偏差中的定位话术与记录要求
  • 管理层：阶段门禁看什么（就绪度、闭环率、误报、采纳率）

最容易失败的人员缺口

  • 有算法、无懂批记录语义的数据产品经理
  • 有系统、无资深工艺固定排期（技转必然空转）
  • 有摄像头、无HR/工会前置沟通（巡检必然受阻）
  • 有模型、无班组回填纪律（预测无法迭代）

PART 08B · 分主线操作细节（现场怎么推）

把“节点”拆到可派工的动作级

① 视频巡检 · 动作包

  • Week 1–4：HR/工会非正式沟通；员工代表访谈；QA/法务用途定位
  • 确定 1 车间 × 5 个最简单可判定动作（如穿戴、区域入侵、关键步骤缺失）
  • 点位清单：视野、光照、遮挡、补点预算
  • 边缘节点上架；仅本地推理
  • 告警台 + 15 分钟确认 SLA
  • 误报样本每周复盘；动作字典迭代
  • 客户告知材料（如涉及）预审
  • Pilot：接入巡检路线，统计“可减少的无效巡检频次”

② 技转辅助 · 动作包

  • M1–M3：反应类型/风险点/设备能力库 schema
  • 锁定 3 类主力反应 + 5 种主流反应器
  • 资深每周 4h：访谈+标注，写入绩效
  • 招/派文档结构化专员；OCR+LLM 半自动
  • 每月入库 5–10 个项目；质量抽检
  • M9+：RAG 检索上线；风险矩阵初稿
  • 机理叠加（传热/传质/放大判据）接口
  • 新项目试点：AI 初稿 → 资深对照 → 差额学习

③ 生产预测 · 动作包

  • 选点：优先“数据齐、痛点清、动作可落地”的单元
  • 冻结标签：不合格/偏差/故障停机的定义与时间窗
  • 打通 IP.21 + LIMS + EBR（+ EAM）
  • 先做可解释基线模型，再上复杂模型
  • 输出建议卡：提前量、依据特征、建议动作、责任岗
  • 班前会试用；采纳/拒绝必填原因
  • 与维护窗口、加严取样、参数回调联动（人工执行）
  • 每 4 周模型复盘：漂移、误报、漏报
现场推进口诀：先闭环、后精度；先单点、后复制；先辅助、后自动化。任何“自动改工艺设定 / 替代签字”都不在本阶段范围。

PART 09 · 治理机制与风险控制

用治理保证 2–3 年“持续有进展”，而不是项目虎头蛇尾

建议治理节奏

  • 周会（运营）：数据就绪度、误报/采纳、阻塞项（PMO 主持）
  • 双周（技术）：模型/接口/安全评审
  • 月度（Sponsor）：KPI 与资源裁决
  • 季度门禁：按 G1–G7 停/扩/转向
  • 变更控制：范围变更必须书面，禁止静默加需求

建议看的运营 KPI（少而硬）

  • ① 误报率、告警闭环时长、员工投诉/接受度
  • ② 结构化入库数、检索可用率、资深工时兑现率
  • ③ 预警有效率、建议采纳率、因建议避免的损失事件数
  • 底座：P0 接口可用率、主数据冲突数、审计抽查通过率

主要风险与控制（按严重度）

风险表现控制
① 员工/组织接受度（巡检） 项目被抵制或暗中不配合 软启动前置；定位“辅助”；员工代表参与设计；权限最小化
② 资深不投入（技转） 知识库空转，模型无料 绩效绑定；署名与激励；AI 不替代签字
③ 数据接不通 / 对不齐 模型无法训练或不可信 0 号工程独立立项；就绪度看板；80/20 策略
④ 客户保密与合同 审计风险、合同违约 隔离策略；边缘本地；合同附件明确内部辅助
⑤ 场景膨胀 两年做完一半功能、零闭环 MVP 门禁；未达标不扩展；PMO 控范围
⑥ 供应商绑定 数据/模型不可迁移 合同约定 IP 与导出；核心知识库自建；分阶段降依赖
⑦ 监管表述过猛 “AI 替代”引发质疑 对外统一“辅助”；保留人工 SOP 与签字

APPENDIX · 一页纸决策摘要

提请确认的 6 件事

1. 范围确认

未来 2–3 年 AI 生产主线是否就收敛为：视频巡检 / 技转辅助 / 生产预测指导？其他方向仅作底座旁路？

2. 0 号工程立项

是否同意将数据底座（取数、主数据、隔离、AI 平台）作为独立项目由 IT 主责推进？

3. 试点对象授权

是否授权 PMO 在 2 周内冻结：1 个巡检车间、3 类技转反应、1 个预测单元？

4. 人员承诺

是否同意核心小队编制 + 资深工艺每周 4 小时知识贡献写入绩效？

5. 定位与对外口径

是否统一对外表述为“AI 辅助”，保留人工巡检与资深签字，不宣称替代？

6. 门禁机制

是否同意按 G0–G7 季度/阶段门禁停扩，未达标不追加扩展预算？

本方案承接既有方向规划中的可复用结论（视觉合规、技转放大、设备/生产数据预测），并按上层最新三条主线重新编排为可执行推进包。 具体供应商选型、精确预算与车间名单需在 G1 数据盘点与现场勘察后固化。
