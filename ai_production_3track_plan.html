PART 01 · 总体定位与子能力地图

三条主线不是三个口号，而是 10 个子能力的组合推进包

2–3 年目标不是“全面智能化”，而是每条主线形成可演示、可验收、可复制的闭环。子能力允许分波次上线，但必须挂在同一底座上。

PART 02 · 整体思路

“底座先行 + 三线并行 + 子能力波次上线”

0 号工程数据底座 / 主数据
客户隔离 / AI 平台
→
① 感知闭环视频巡检 + 电子点检
先可见、快闭环
→
③ 指导闭环报告 / QC / 失误
黄金参数进班组
→
② 知识闭环放大 / 审查 / 复核
先结构化再 AI

为什么这样排

  • ①：CCTV/点检基础相对现成，组织风险大 → 软启动后做“看得见的闭环”。
  • ③：可快速产生工时节省（报告）与可量化风险收益（QC/失误/黄金参数）。
  • ②：价值最大但知识工程最重 → 长期 IP 资产建设，不能急着上模型。

三条纪律

  • 共用底座：批号/项目/设备/客户隔离一次建好。
  • 场景收敛：每个子能力先做一个最小闭环，禁止一上来全覆盖。
  • 人在环路：告警必确认；审查/复核必资深签字；预测建议必有采纳/拒绝记录。
阶段时间核心任务领导可见产出

闭环期Y1 Q3–Y2 Q2子能力各自跑通“数据→模型→动作→复盘”试点 KPI、流程改造、运营手册

PART 03 · 三条主线边界（做什么 / 不做什么）

先钉死范围，避免项目膨胀成“大而全”

TRACK 01

视频巡检 + 电子点检

要做：关键区视频合规监测；动态点检任务；拍照异常识别；告警/工单闭环；与培训反馈联动。

不做：PoC 不做实名识别；不做精细手部微操作；不宣称“AI 替代巡检员/点检员”。
TRACK 02

放大建议 · 工艺审查 · AI 复核

要做：历史项目结构化；放大参数/设备建议；工艺审查风险矩阵；AI 复核遗漏与不一致提示。

不做：不做新反应发明；不做无资深签字的自动通过；客户间不共享具体 CPP/CQA 数值。
TRACK 03

报告 · QC · 失误 · 黄金参数

要做：Campaign/MOR 等草稿；QC 结果区间预测；高风险步骤/失误预警；黄金参数窗口指导生产。

不做：不做 AI 替代 QC 检测；不做自动改 DCS 设定；APR 等强监管报告后置。

子能力输入系统动作人的动作验收口径
视频巡检1 车间点位流 + 5 动作字典违规/缺失告警15 分钟内确认误报≤10%；闭环率≥90%
电子点检设备点检项 + 历史 + 可选传感动态任务 + 拍照识别点检员执行/复核漏检下降；异常识别可用
放大/审查/复核3 类反应历史包 + 设备能力库建议+风险矩阵+复核清单资深签字≥20 项目入库；初稿可用≥60%
AI 报告MES/LIMS/QMS/IP.21 字段按模板生成草稿+引用工程师定稿工时节省≥40%；来源可点
QC/失误/黄金参数工艺时序+质检+偏差标签预测/预警/参数窗口班组采纳回填有解释；有采纳记录；无自动改设定

SCENE 01 · 主线① 应用场景与现场做法

视频巡检 + 电子点检：从“人走了就是盲区”到“感知—告警—处置”

场景 A · GMP 车间视频辅助巡检

典型现场：称量间 / 投料区 / 洁净走廊更衣节点 / 废弃物暂存口等关键操作区。

  • 触发：摄像头持续取流，边缘 AI 按动作字典实时推理
  • 识别对象（PoC 先做简单项）：未按规定穿戴、禁入区域闯入、关键步骤长时间缺失、通道堵塞等
  • 系统动作：弹告警 + 截取 10–30 秒短视频存证 + 生成巡检待办
  • 人的动作：巡检员确认真/误报 → 现场纠正或开偏差 → 培训部回收高频误操作做复训
  • 日清：班组长看“告警闭环率 / 误报 Top”；QA 抽查存证与处置记录

场景 B · 设备电子点检（含 AI 层）

典型现场：动力站泵/风机/冷机；生产反应器附属设备；公用工程关键机泵。

  • 触发：每日/每班点检计划；或 DCS/振动异常升高时动态加检
  • 系统动作：推送“今日必检清单 + 重点关注项”；点检员拍照/填数后 AI 识别渗漏、表计异常、外观缺陷；趋势异常自动升工单
  • 人的动作：按路径点检 → 确认 AI 提示 → 异常转 EAM 工单 → 维修回填
  • 与视频协同：同一设备台账；点检异常可调阅相关摄像头时段；维护窗口可同步降低该区域误报阈值

现场一天怎么跑（做法）

1
班前：任务与风险预置
点检 APP 下发动态任务；巡检看板显示昨夜未闭环告警；班组长分配责任人。
2
班中：感知与处置
视频告警进对讲/手机；点检员按路径执行并拍照；真警现场纠正，误报一键标记并进入周复盘样本库。
3
班后：复盘与沉淀
统计漏检、误报、重复告警点位；更新动作字典/点检项；高频问题转培训或 SOP 修订建议。
关键话术：系统是“辅助巡检员/点检员提高覆盖率”，不是监控个人绩效工具。权限最小化，短视频仅事件相关片段留存。

SCENE 02 · 主线② 应用场景与现场做法

放大建议 + 工艺审查 + AI 复核：让“老法师经验”变成可复用能力

场景 C · 放大建议

  • 何时用：中试→商业化、换反应器、换场地、产能爬坡
  • 输入：目标产能、反应类型、现有小试/中试包、候选设备清单
  • AI 输出：相似历史案例；推荐设备/搅拌/传热窗口；关键风险点与建议实验矩阵
  • 人：工艺工程师筛选 → 资深确认 → 写入技转计划

场景 D · 工艺审查

  • 何时用：技转包评审、变更前审查、Campaign 前 readiness
  • 输入：工艺描述、CPP/CQA、设备能力、历史偏差
  • AI 输出：风险矩阵初稿；缺失文件/数据清单；与历史失败模式对照
  • 人：审查会用初稿开场，专家补刀并签字

场景 E · AI 复核能力

  • 何时用：批记录/技转文件/变更文件提交前的“第二双眼睛”
  • 输入：待复核文件 + SOP/规格/相似批/历史 CAPA
  • AI 输出：不一致项、遗漏项、超窗口参数、未关闭偏差关联提示
  • 人：复核人逐条确认；AI 不替代 QA/工艺签字

AI 复核“查什么”（清单示例）

  • 关键参数是否落在历史成功黄金带 / 注册规格内
  • 步骤顺序、取样点、IPC 是否与现行 SOP 一致
  • 设备能力（传热/搅拌/材质）是否覆盖拟放大规模
  • 未关闭偏差 / 变更是否影响本次生产
  • 客户特殊要求条款是否被遗漏

落地前置条件（做不到就别急着上 AI）

  • 反应类型 / 风险点 / 设备能力库 schema 先定
  • 资深每周固定 4 小时知识贡献写进绩效
  • 客户隔离：只学规律，不串具体参数
  • 机理约束（Aspen/经验放大判据）必须叠加，纯文本 RAG 不够

SCENE 03 · 主线③ 应用场景与现场做法（上）

AI 报告撰写 + QC 结果预测：把“汇编”和“事后才知道”变成可提前动作

场景 F · Campaign Report / MOR 等 AI 撰写

使用者：工艺 / 生产技术 / QA。报告是对外交付与对内沉淀双重身份。

  • 触发：Campaign 结束 / 月末 MOR 节点，一键“生成草稿”
  • 取数：MES·EBR 批摘要、LIMS 结果与趋势、QMS 偏差/变更、IP.21 关键参数窗口、SAP 产量交期（按报告类型）
  • AI 动作：按公司模板生成章节；每段附数据引用；异常段高亮并给候选表述
  • 人的动作：工程师按章节审核 → 改写结论性段落 → 签字发布
  • 推进顺序：先 Campaign → 再 MOR / 偏差总结 → APR 与客户定制报告后置

场景 G · QC 结果预测（非替代检测）

使用者：QC / 工艺 / 生产。目标是提前看见风险，不是取消实验室。

  • 触发：批进行到设定里程碑（如关键步骤完成 / 批末）
  • 输入：本批工艺轨迹 + 原料 COA + 历史同类批 IPC/QC +（如有）PAT
  • 输出：各 CQA 预测区间 + 置信度 + 主要贡献特征；高风险提示“建议加严取样/暂停下一步”
  • 集成：LIMS/批监控看板嵌入“AI 预测卡”
  • 人的动作：工艺/QC 会商；最终以实测放行为准

Campaign 草稿生成做法（逐步）

步骤系统工程师质量要求
1. 选项目/批次范围拉取批清单与状态确认范围与模板版本批号映射正确
2. 跨系统取数组装事实表补 20% 缺失字段字段来源可追溯
3. 章节生成RAG+模板填充重点改“结论/讨论”每段可点开来源
4. 异常解释辅助关联偏差与参数偏移确认因果表述禁止无依据推断
5. 定稿发布版本归档签字保留 AI/人工差异日志

SCENE 03B · 主线③ 应用场景与现场做法（下）

失误预测 + 黄金参数：把经验窗口变成班组可执行的指导

场景 H · 失误 / 偏差风险预测

  • 定义：预测“这批/这一步更可能出人为或过程失误”，不是事后写偏差
  • 信号来源：参数逼近限、加料窗口过窄、换班节点、设备亚健康、历史同一步高偏差率、新人上岗等
  • 系统输出：步骤级风险分数 + 原因标签 + 建议防护（双人复核、降速、加取样、资深在场）
  • 现场用法：班前会播报今日高风险步骤；班中看板常亮；事件后回填是否命中
  • 边界：预警指导行为，不自动锁机（除非另立安全联锁项目）

场景 I · 黄金参数指导生产

  • 定义：从高成功批次中沉淀“更稳的操作窗口”，用于设定建议与实时监控
  • 构建：历史成功批聚类 → 关键 CPP 黄金带（中心+带宽）→ 分设备/分季节版本管理
  • 开批前：给出推荐设定与监控优先级（相对注册宽限更“好打”的子窗口）
  • 批中：实时对比黄金带，偏离则提示回调建议与相似成功批对照
  • 批后：成功则强化窗口；失败则触发窗口版本复审
  • 边界：黄金带 ≤ 注册/验证范围；更改设定必须走人工与变更流程

班组侧一日闭环（做法）

早
班前会：风险 + 黄金参数
播报本班高风险步骤、设备健康提示、本批黄金参数卡；确认双人复核点。
中
批中监控：预测卡 + 偏离提示
QC 预测更新；参数偏离黄金带告警；班组长决定采纳回调/加取样，并在系统点“采纳/拒绝+原因”。
晚
复盘：命中率与窗口迭代
统计预警命中、建议采纳效果；工艺周会决定是否更新黄金参数版本；报告草稿自动预生成待写章节。
四件事必须一起做才叫“指导生产”：QC 预测看见质量风险 → 失误预测看见人为/过程风险 → 黄金参数给出怎么打 → 报告把结果沉淀为可审计知识。

PART 05 · 软硬件基础（细节版 · 上）

  • 边缘节点上架；点检 APP 对接 EAM
  • 告警 15 分钟 SLA；误报周复盘
  • 动态点检规则：按健康度/季节加检
  • Pilot：巡检路线改造 + 培训闭环

② 放大 / 审查 / 复核

  • M1–3：分类法与设备能力 schema
  • 锁定 3 类反应 + 5 种反应器
  • 资深每周 4h；结构化专员到位
  • 每月入库 5–10 项目
  • 放大建议与风险矩阵工作台
  • 配置 AI 复核规则库（规格/SOP/偏差）
  • 新项目：建议→审查→复核→签字试点

③ 报告 / QC / 失误 / 黄金

  • 冻结 1 个 Campaign 模板与字段字典
  • 打通 MES/LIMS/QMS/IP.21 取数
  • Campaign 草稿 PoC（带来源）
  • 选 1 项目 3 个 CQA 做回测
  • 定义失误标签与步骤风险特征
  • 构建黄金参数 V1 并班前会试用
  • 采纳/拒绝回填纪律；每 4 周复盘
  • 再扩 MOR；APR 后置
口诀：先闭环、后精度；先单点、后复制；先辅助、后自动化。任何“自动改设定 / 替代检测或签字”都不在本阶段。

PART 09 · 治理与风险

用门禁和 KPI 保证 2–3 年不断档

治理节奏

  • 周会：就绪度、误报、采纳、阻塞
  • 双周：模型/接口/安全评审
  • 月度 Sponsor：资源与范围裁决
  • 季度门禁：停 / 扩 / 转向

少而硬的 KPI

  • ① 误报率、闭环时长、点检漏检率、接受度
  • ② 入库数、建议采用率、复核问题命中率、资深工时兑现
  • ③ 报告工时节省、QC 预测可用率、预警命中、黄金参数采纳
  • 底座：P0 接口可用率、审计抽查通过率
风险表现控制
员工接受度（巡检）抵制或不配合确认软启动；辅助定位；权限最小化
点检形式化只扫码拍照应付动态任务+识别抽检+与工单联动
资深不投入（技转）复核规则空心绩效绑定；署名激励；不替代签字
报告幻觉/无来源不可审计强制引用；禁无依据结论段自动定稿
QC 预测被误读为放行合规风险界面明确“预测≠放行”；实测为准
黄金参数越权改设定变更失控只建议；改设定走变更/权限
客户保密串数据/视频泄密隔离、边缘本地、合同附件
场景膨胀两年无闭环MVP 门禁；未达标不扩展

APPENDIX · 提请确认

请领导确认的 7 件事

1. 主线范围

① = 视频巡检 + 电子点检；② = 放大建议 + 工艺审查 + AI 复核；③ = AI 报告（Campaign/MOR 等）+ QC 预测 + 失误预测 + 黄金参数。是否按此收敛？

2. 0 号工程

数据底座（取数、主数据、隔离、AI 平台）是否独立立项，IT 主责？

3. 试点冻结授权

是否授权 2 周内冻结：1 巡检车间、1 点检区域、3 类反应、1 个 Campaign 项目、1 个 QC/黄金参数单元？

4. 人员承诺

核心小队编制 + 资深每周 4 小时知识/复核规则贡献是否写入绩效？

5. 对外口径

统一“AI 辅助”；不替代巡检/点检/QC 检测/签字放行。是否确认？

6. 门禁机制

按 G0–G7 停扩；未达标不追加扩展预算。是否确认？

7. 软硬件原则

视频边缘本地处理不上公有云；核心知识库与复核规则归属凯莱英；预测/黄金参数只出建议卡，不直连改 DCS。是否作为建设硬约束？

V1.1 在 V1.0 基础上扩展子能力与场景做法，并细化软硬件分层（L1–L5）。具体供应商选型、精确预算与车间名单在 G1 盘点与现场勘察后固化。
