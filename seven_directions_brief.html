方向 1 · 批次放行预测 + QC 报告 AI 起草

用历史 + 实时数据预测当批 QC 结果，自动生成放行建议

主要用户：QC / QA / 工艺研发 执行难度 ★★★★ BDCT（批次综合检测）升级

解决的场景

目前批次放行流程：本批生产结束 → 取样 → QC 实验室全检（HPLC 含量 / 有关物质、KF 水分、晶型 XRD、粒度等）→ 出报告 → QA 审核 → 放行。痛点是"做完批才知道结果"， 一旦 QC 不合格只能降级 / 返工 / 报废，损失最大。

AI 升级后：在批生产结束前甚至中期，用历史同类批次数据 + 本批工艺数据 + 在线 PAT 数据， 预测本批 QC 结果范围，提前给出"高概率合格 / 需重点关注 X 项 / 高风险不合格"判断， 并自动生成 QC 报告草稿（结构、表格、趋势图、合规声明）。

输入 / 输出

📥 输入数据
  • 历史同类批次：同一项目 / 工艺路线的所有历史批 IPC + QC 结果
  • 本批生产数据：反应釜温度 / 压力 / pH / 搅拌 / 加料速率（DCS/IP.21）
  • 原料 COA：本批使用原料的供应商批号、含量、有关物质谱
  • 过程 PAT 数据（如有）：在线 IR / NIR / Raman 光谱、HPLC 在线监测
  • 设备状态：本批使用反应器的清洁验证、上一批生产物料、维护记录
  • 环境数据：温湿度、洁净度、压差
  • SOP / 工艺规范：CPP（关键工艺参数）+ CQA（关键质量属性）字典
📤 输出
  • 各 QC 项预测值 + 置信区间：含量 99.2 ± 0.4% / 杂质 A 0.08 ± 0.03% / 水分 0.15 ± 0.05%...
  • 合规风险分级：🟢 高概率合格 / 🟡 需重点复核 X 项 / 🔴 高风险，建议过程干预
  • QC 报告草稿：结构化模板填充 + 数据图表 + 趋势对比 + 合规声明
  • 放行决策建议：直接放行 / 留样复核 / 全检确认 / 工艺干预
  • 风险溯源：若预测高风险 → 给出最可能的 3 个根因（原料 / 工艺参数 / 设备）

AI 能做到多好

同项目内预测（数据多）

连续生产 30+ 批后，主要 CQA 预测±5% 以内准确率可达 80-90%。 含量、水分等简单项目可到 95%+。

同项目早期（数据少）

前 5-10 批数据不够，单批预测置信度低。需借助贝叶斯先验或迁移学习，效果中等。

跨项目预测

不同客户、不同分子的项目"经验互通"受 CDMO 客户隔离限制。 只能学方法论 / 工艺规律，不能学具体参数。

执行难度与卡点

🟡 数据 / 技术卡点

  • CDMO 单项目批次稀疏：1 个项目可能就 5-30 批，对 AI 来说"小数据"，模型方差大
  • 原料 COA 与生产数据关联不足，原料供应商数据接入难度大
  • 在线 PAT 数据存在但历史归档质量参差，需要重新对齐
  • 偏差批次（不合格批）少，训练负样本不足

🔴 业务 / 合规卡点

  • 跨项目客户数据隔离：不同客户的工艺经验不能互通，限制 AI 学习范围
  • GMP 监管认可：QC 报告 + 放行决策是 GMP 强监管项，AI 起草 ≠ AI 决策，最终签字仍要 QC 工程师
  • FDA / EU 检查应对：AI 模型需做 GAMP 5 类别 4 验证 + 周期性再验证
  • QA 部门对 AI 黑盒决策本能抗拒，需要可解释性（每个预测要能给出依据）

方向 2 · 生产技术报告 AI 辅助撰写

Campaign Report / MOR / APR — 从数据到报告的自动化路径

主要用户：工艺研发 / 生产 / QA 执行难度 ★★（相对低） 短期最易出成果的方向

解决的场景

凯莱英每个项目都要写多种结构化报告： Campaign Report（一个生产 campaign / 周期的总结）、 MOR (Manufacturing Operations Review)（月度运营评审）、 APR (Annual Product Review)（年度产品质量回顾）、 偏差总结报告、CAPA 关闭报告、客户技术报告 等。

痛点是这些报告里 70-80% 的内容是"机械汇编"—— 从 MES 抓批次清单、从 EBR 抓 IPC 数据、 从 QMS 抓偏差和 CAPA、从 SAP 抓物料消耗、从 LIMS 抓 QC 结果 ...... 资深工程师花1-2 周把数据"拼"成报告，其中真正需要专家判断的只有 20-30%（趋势分析、结论、改善建议）。

AI 把"机械汇编"那 70-80% 自动化，工程师只做"专家判断"那 20-30%。

输入 / 输出

📥 输入数据源
  • MES / EBR：批次清单、批记录、IPC 数据、工艺步骤实际执行参数
  • LIMS：QC 检测结果、放行状态、留样信息
  • QMS：偏差记录、CAPA 任务、变更控制、客户投诉
  • SAP：物料消耗、成本数据、收率、库存变动
  • EAM / CMMS：设备维护、停机时间、清洁验证
  • 设备 DCS / IP.21：关键工艺参数趋势数据
  • 报告模板库：客户专属 / 凯莱英标准 / 监管要求
  • 历史已通过审核的报告：作为风格 / 措辞参考
📤 输出
  • 结构化报告草稿：按模板填充，含执行摘要、批次清单、KPI 表、趋势图、偏差汇总、CAPA 状态等
  • 关键趋势分析：自动识别"本周期 vs 上周期 / 历史"的偏离项目
  • 异常事件梳理：本周期所有偏差按严重程度排序、根因分类、CAPA 关闭情况
  • 数据图表：自动生成 Pareto 图、控制图、Sankey 流向、批次趋势对比
  • 改善建议初稿：基于历史模式给出 3-5 条候选建议供工程师采纳/修改
  • 合规声明：自动填充 GMP 必须的段落（如 "本期所有偏差均已完成 CAPA 关闭，对产品质量无影响"）

AI 能做到多好

结构化数据填充

批次清单 / KPI 表 / 偏差汇总等"机械汇编"部分 → 95%+ 准确度，几乎不需要修改。

数据可视化

趋势图、控制图、Pareto 图等 → 90% 一次性可用，少量需要工程师调整坐标轴或标注。

结论 / 改善建议

AI 给出建议初稿 → 工程师采纳率50-70%，剩余需要专家修改 / 补充行业洞察。

执行难度与卡点

🟡 主要工程问题

  • 数据源散落：MES / QMS / LIMS / EBR / SAP 各自独立，跨系统取数需要建中间层
  • 报告模板多：每个客户、每种报告类型模板不同，需要把模板"结构化"为 AI 能识别的格式
  • 历史报告大量是 Word / PDF，需要先做报告语料库结构化
  • 每种报告需要单独验证一次（虽然每个验证周期短）

🟢 相对低的卡点

  • 不涉及生产决策：报告撰写是"事后总结"，不直接影响放行 / 投料，监管敏感度低
  • 有兜底：所有报告最终由工程师审核签字，AI 出错不会直接到客户手里
  • 价值显性：每份报告省工程师 5-10 工时，规模化后效益明显
  • 市场上有成熟产品（如 IDBS / Schrödinger LiveDesign / 各家 LLM + RAG 方案）

方向 3 · AI 辅助技术转移与工艺放大评估

R&D 工艺包审查 + 反应器放大风险识别 + 推荐参数

主要用户：技术转移团队 / 工艺研发 / 生产 执行难度 ★★★★ CDMO 核心命脉之一

解决的场景

技术转移是 CDMO 业务的"心脏" —— 一个新项目从研发到中试到商业化，要经历工艺包审查 → 设备等效性评估 → 放大风险识别 → 试生产 → 工艺验证 → 正式生产。 其中工艺审查和放大建议最依赖资深专家的"工程化经验"，是凯莱英老法师们的核心价值。

痛点：（1）资深工艺工程师产能有限，新项目排队等审查；（2）隐性知识分散在不同部门，新人不易传承；（3）放大风险点经常"踩坑后才发现"。

AI 升级思路：把凯莱英历史项目的"工艺审查清单 + 放大风险库 + 等效性映射表"结构化沉淀， 新项目进来时 AI 自动给出"工艺审查初稿 + 风险点矩阵 + 推荐放大参数"， 资深工程师从"全部从头做"变成"审核 + 补充经验"，产能放大。

输入 / 输出

📥 输入
  • R&D 工艺包：合成路线、反应条件、催化剂体系、表征数据、原料质量要求
  • R&D 反应器规格：50L 玻璃 / 100L 哈氏合金 / 等
  • 目标商业化反应器规格：500L / 5000L / 反应器材质 / 搅拌型式
  • 历史相似反应数据库：凯莱英过去 10 年的同类反应案例 + 风险点 + 放大经验
  • 设备能力库：每个反应器抽象为 30+ 工程参数（传质 / 传热 / 搅拌等）
  • 客户专属约束：杂质限度、晶型要求、特殊监管要求
📤 输出
  • 工艺审查清单：按"安全 / 质量 / 收率 / 成本 / 合规" 5 维度自动审查，每条标 🟢🟡🔴
  • 放大风险矩阵：识别本工艺在目标反应器上的 5-15 个潜在风险点（如放热不均、晶型偏移、混合时间过长）
  • 推荐放大参数：搅拌转速、加料速率、夹套温度、停留时间等的初始建议值
  • PoC 实验设计：如某个风险点需要实验确认，AI 给出实验设计建议（DoE）
  • 历史相似案例引用：每个风险点都附"凯莱英历史项目 XXX 遇到过类似情况，解决方案是 ..."
  • 设备等效性比对：R&D vs 商业化反应器的关键工程参数对比表

AI 能做到多好

风险点覆盖

通过结构化历史项目库，AI 可识别80% 已知风险点，资深工程师在此基础上补充 20% 新风险。

放大参数推荐

基于物理传质 / 传热相似准则 + 历史数据，参数推荐方向正确 90%、精度 ±20%，仍需 PoC 实验确认。

资深专家产能

从"全部从头审查"变为"审核 + 补充" → 资深工程师产能 +50-100%，新人成长加速。

执行难度与卡点

🔴 最大卡点 · 历史项目知识结构化

  • 凯莱英过去 10 年项目数据大量沉淀在 Word / PDF / Excel，AI 不能直接读取
  • 资深工程师的"隐性知识"分散在不同人脑中，没有系统化记录
  • 历史项目库结构化是6-12 个月的专项工作，需要资深工程师配合
  • 不同部门的项目分类标准不一致（化学反应类型、设备型号、客户要求）

🟡 物理放大规律 — AI 帮不了的部分

  • 反应器从 50L 放大到 5000L，物理传质 / 传热规律完全不同，纯数据 AI 推断不够
  • 需要叠加化工机理模型（CFD + Aspen Plus）才能给可靠的物理参数
  • 催化体系 / 副反应 / 杂质生成路径等深层化学问题仍需化学家判断
  • AI 在此场景的定位是"放大资深工程师的产能"而非"替代化学家"

解决的场景

凯莱英目前已有 EAM / CMMS 等设备管理系统，但主要做的是"记录" —— 点检表打勾、备件出入库、维护工单。 5 个子模块需要 AI 升级，把"记录系统"升级成"决策辅助系统"。

这 5 个子模块共享一个底层数据基础： 设备 BOM + 原理图 + 运行历史 + 维护历史 + 备件清单 + 故障案例库。 建好这个数据基础后，5 个 AI 应用可以"同时启动"，是典型的"一笔投入多个应用受益"方向。

5 个子模块切换

📥 输入
  • 每台设备的点检项清单 + 历史点检记录

  • 设备维护历史 + 已发现的故障
  • SOP / 验证文件
📤 输出
  • 动态点检任务：今天哪些设备需要点检 + 重点关注项
  • 异常实时识别：点检员拍照 / 填表后 AI 立即识别异常项
  • 历史趋势可视化：单台设备 30 天点检项目变化
  • 点检效率 KPI：班组 / 个人 / 设备级统计

AI 能做到多好

电子点检是 5 个子模块中最容易做的。市场上有成熟产品（钉钉点检 / 蓝凌等）， AI 层的价值在"动态任务推荐 + 拍照异常识别"，预计可达 90%+ 准确度。

📥 输入
  • 备件主数据 + 设备 BOM（哪个备件给哪台设备）
  • 历史出入库记录 + 故障 - 备件关联记录
  • 设备运行小时数 + 当前健康状态
  • 备件供应商 / 交期 / 库存策略
📤 输出
  • 需求预测：未来 3-12 个月各类备件需求量预测
  • 智能采购建议：什么时候 / 买多少 / 谁的交期最快
  • 呆滞备件识别：超过 N 年未用的备件提示报废 / 流转
  • 关键备件预警：高故障率设备的关键备件库存预警

AI 能做到多好

备件预测属于"中等难度"。简单的 ABC 分类 + 季节性预测准确度高（85%+）， 但低频高价值备件（如进口主轴、特殊密封件）预测难度大，AI 给建议、人工决策仍是主流。

📥 输入
  • 设备 DCS / SCADA 实时运行数据（温度 / 压力 / 振动 / 电流）
  • 独立 PdM 传感器（振动 / 电流 / 油液）
  • 设备维护历史 + 故障样本
  • 跟智现未来 / 和利时 / 信力共擎等专精厂商的算法对接
📤 输出
  • 设备健康分数：0-100 实时分数 + 30 天趋势
  • 剩余寿命 RUL 预测：带置信区间（如"11±3 天后跌破阈值"）
  • 故障模式预判：基于异常模式给出最可能的故障类型
  • 维护工单自动派单：跟 EAM 联动派工

AI 能做到多好

PdM 是 5 个模块中技术成熟度最高的（智现未来在半导体光刻机做了 20+ 年）， 但制药行业落地仍受"故障样本少 + 设备多样性大"限制， 关键设备（冰机 / 离心机 / 压缩机）70%+ 准确度可达，但全厂全设备 PdM 难度大。

📥 输入
  • 历史 IQ / OQ / PQ 验证报告（语料库）

  • 验证报告草稿：执行后数据填充 + 结论生成
  • 差距分析：跟以往同类设备验证方案的差异点 + 解释

AI 能做到多好

📥 输入
  • 故障 / 安全事件描述（文字 + 照片 + 视频）

  • 历史类似故障案例库
  • 设备维护 / 改造历史
📤 输出
  • 故障 / 事件根因分析报告：基于设备原理 + DCS 数据 + 历史案例给出根因排序

  • 5 Why + 鱼骨图分析草稿
  • CAPA 建议：纠正措施 + 预防措施初稿
  • 同类设备风险提示：相同 / 相似设备需要同步检查的清单

AI 能做到多好

故障调查是 5 个模块里最难的。需要 AI 同时理解： ① 设备原理（BOM / 图纸数字化）② 当时的物理过程（DCS 数据）③ 历史类似案例（语料库）④ 化工 / 机械专业知识。 目前能做到50% 根因分析正确、80% 给出有价值的调查方向，仍需资深工程师定论。

解决的场景

GMP 强制要求双人复核（Two-Person Verification）的场景非常多： 投料量复核、配方计算复核、批记录数据校验、报告数字一致性、关键签字确认、参数变更复核、清洁验证结果核对 等。 现状：第二人往往"占用了一个高级别员工的时间"，且"两人都看一眼，反而互相依赖"。

AI 复核思路：在"规则明确、有标准答案"的复核场景，让 AI 做第二人 —— 第一人输入 → AI 实时核对 → 一致则放行，不一致则三人介入（第一人 + AI + 真人复核员）。

关键边界：AI 复核不是替代所有第二人，而是替代"规则明确的部分"，把人力释放到"需要专家判断"的复核上。

典型应用场景

📦 投料复核

称量结果 vs 配方单 vs 批生产指令单的一致性。 AI 准确度 99%+

🧮 配方计算复核

起始物料投料量 → 中间体 → 最终产物的理论收率 / 限量计算。 AI 准确度 99%+

📋 批记录数据校验

实际操作参数 vs 工艺范围；时间戳一致性；签字完整性。 AI 准确度 95-99%

📊 报告数字一致性

同一份报告中相同数字在不同位置出现是否一致；图表 vs 文字 vs 表格。 AI 准确度 99%+

✏️ 关键签字确认

签字人资质 / 时间戳 / 权限范围核查。 AI 准确度 99%+

🔄 参数变更复核

变更前后参数差异是否在允许范围；影响范围评估。 AI 准确度 80-90%

🧹 清洁验证核对

CIP 各阶段参数 vs 验证范围；LIMS 结果 vs 接受标准。 AI 准确度 95%+

🔴 核心卡点 · GMP 监管认可

  • FDA 21 CFR Part 11 + EU Annex 11 对"电子记录电子签字"已有明确规则；但对"AI 作为第二人"的态度尚未完全明确
  • FDA CSA 2025-09 + EU GMP Annex 22 已开门 —— 明确支持 AI/ML 在 GxP 用，含放行决策辅助
  • 但 客户审计 / NMPA / FDA 检查时，需要逐项解释"AI 复核 SOP + 验证证据 + 失效兜底"
  • 需要凯莱英自己写一套"AI 复核 SOP + 验证主计划"，作为客户审计应对材料

🟡 业务 / 工程问题

  • 责任划分：AI 复核出错谁负责？需要明确"AI 是工具，签字人仍是责任人"
  • 规则结构化：每种复核场景的 SOP 规则要先结构化（非自然语言），工程师工作量大
  • 异常升级机制：AI 不确定时要"升级到真人"，触发阈值需要调优
  • 客户接受度：不同客户对 AI 介入 GMP 复核的态度不同，可能需要客户特殊豁免

4 个共同前置 + 4 个共同卡点 + 4 个共同疑问

汇报最后，把 7 个方向的共同特性抽出来 —— 这些是无论哪个方向先做，都需要凯莱英思考的问题。 本汇报不下结论、不排优先级，把这些共性留给后续评估讨论。

🟢 4 个共同前置 — 哪个方向先做都要先有这些

  • 数据底座：MES / EBR / LIMS / QMS / IP.21 / SAP / EAM 多系统数据打通
  • 主数据治理：批号 / 项目 / 客户 / 设备 / 物料 主数据统一
  • 报告模板 / SOP 结构化：现有 Word / PDF 资料 → AI 可读格式
  • 设备 BOM + P&ID 数字化：方向 4 设备 AI 的基础

🟡 4 个共同卡点

  • 客户数据隔离：CDMO 多客户业务里 AI 学习边界（哪些可跨项目、哪些不可）
  • GMP / GxP 合规：每个方向都要做 AI 系统验证（GAMP 5）+ 客户审计应对
  • AI 辅助 vs AI 主导：哪些场景 AI 出建议、哪些场景 AI 直接判决
  • 责任划分：AI 出错谁负责？签字人 vs AI 工具供应商 vs 凯莱英 IT

🔵 4 个共同疑问 — 留给后续评估

  • 先做哪个？ 短期 ROI 最显性的（方向 2 报告 / 方向 6 培训）vs 长期价值最大的（方向 1 QC / 方向 3 技转）
  • 谁来做？ 一个供应商打包 vs 多个专精供应商组合 vs 凯莱英自建
  • 多大投入？ 每个方向单独 PoC（200-500 万/项）vs 平台化总集成（千万级）
  • 多大节奏？ 同时启动 3-4 个方向 vs 串行依次推进
