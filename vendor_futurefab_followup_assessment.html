PART 03 · 半导体 ↔ CDMO 制药 术语对照

把智现未来的"行话"翻译成凯莱英能听懂的话 — 这是平移可行性的基础

业界很少有人把这两个行业放在一起讲，但"软"的逻辑层（数据建模、批次追溯、根因分析、AI 算法）出奇地相似， "硬"的物理层（设备、工艺、合规）完全不同。下表把核心术语逐项对应起来，理解这张表是后续所有方案的前提。

概念域 半导体（智现未来主场） CDMO 制药（凯莱英） 相似度 / 差异说明
生产单元 Wafer / Lot（晶圆 / 批次，每片或每盒 25 片） Batch / Lot（批次，每批数百公斤到吨级） ★★★ 高度同构
都是"独立可追溯的最小生产单元"，都有 ID、家谱、产出物属性
生产履历 Lot Genealogy + WRA（Wafer Run-time Analysis） Batch Record (MBR/EBR) + 物料谱系 ★★★
都是"完整记录每一步操作 + 参数 + 设备"
最优生产路径 Golden Path（黄金路径，最佳工艺组合） Golden Batch（黄金批次 / Optimal Run） ★★★
逻辑完全一致，都是"找出历史最好批次的工艺参数轨迹作为新批次模板"
实时多参数监控 FDC（Fault Detection & Classification） 过程偏差实时监控（业界还在初级阶段，多数厂仍是单点阈值） ★★★
CDMO 比半导体落后 5-10 年，引入后效益巨大
工艺配方 Recipe（每步几十个参数） MBR + SOP + CPP/CQA ★★ 概念同构、形式不同
CDMO 配方有 GMP 监管要求，每个变更都要 Change Control
批间反馈优化 R2R（Run-to-Run Control） DoE 自动化 / 贝叶斯优化 / 黄金批次反馈 ★★★
凯莱英连续流是天然的 R2R 平台
异常 / 超规 OOS / Excursion（Out-Of-Spec） Deviation / OOS ★★★
流程相似（发现 → 调查 → CAPA），CDMO 多了 GMP 文档体系
根因分析 RCA Auto-Trace（YES 自动溯因） CAPA Root Cause ★★★
智现未来 YES 自动溯因可直接迁移为 CAPA Copilot
业务模型 Foundry（代工模式，同产线为多个 IC 设计公司代工） CDMO（代工模式，同产线为多个药企代工） ★★★ 高度同构
"产线复用 + 客户隔离"的核心管理逻辑相同
客户数据 Customer Wafer Design（客户产品设计绝密） 客户 API / 工艺包（客户产品工艺绝密） ★★★ 同构
客户隔离要求严苛程度相同；解决方案可借鉴
设备类型 光刻机 / 刻蚀机 / CVD / CMP 反应釜 / 结晶器 / 干燥机 / 离心机 ★ 完全不同
物理层、传感器、控制系统差异巨大，要重做
合规体系 IATF / ISO 9001 / 客户审计 21 CFR Part 11 + GAMP 5 + GMP + NMPA ★ 完全不同
CDMO 合规要求严得多；智现未来需补 GAMP 5 类别 4 验证
DCS / OT 协议 SEMI E10/E30/E40/E87（半导体专属） OPC UA + Modbus + DCS 厂商专属（Honeywell / 横河 / Emerson / 西门子） ★ 完全不同
智现未来产品需做制药 DCS 接口适配
AI 算法适用性 PCA / Autoencoder / LSTM / RL / MPC / 大模型 + RAG 同类算法直接适用 ★★★ 完全相同
数学模型层无任何差异
一句话总结：业务逻辑层和算法层 可平移；物理设备层、合规层、协议层 需重做。 平移工作的 70% 难度在"重做"那 3 层。

PART 04 · 7 个产品在凯莱英的具体应用场景

每个场景:输入 → AI 处理 → 输出 → 解决什么问题 → 边界 → 优先级

这是这份汇报的"工程深度部分"。每个场景都按工艺工程师能验收的颗粒度写。 场景 1 之后还有专门一个交互 demo 展示 FDC 怎么在反应釜上跑。

① FDC → 反应/结晶过程的多变量偏差实时监控

优先级 ★★★ 强烈推荐第一个 PoC

在反应过程中实时融合温度、压力、流量、pH、UV、IR 等 20-50 个传感器数据， 用多变量异常检测（PCA / Autoencoder / Hotelling T²）发现"每个参数单看都正常、但组合起来反常"的早期偏差， 并自动分类成已知偏差模式，秒级推送给工艺工程师。

输入
• DCS 实时数据（20-50 tag × 秒级）
• 在线 PAT（IR / 拉曼 / HPLC）
• 历史批次偏差标注库
• 当前批次工艺配方
AI 处理
• 多变量统计模型（PCA / T² / SPE）
• 异常检测（Autoencoder / LSTM）
• 已知偏差分类器（已训练）
• RCA 关联检索
输出
• 异常事件 + 严重等级 + 时间戳
• 自动分类的偏差类型
• 推荐响应动作（推 SCADA + 移动 APP）
• 偏差调查初稿（推 QA Copilot）
解决什么问题
  • 传统 SCADA 单点阈值报警漏报误报多（典型漏报率 30%+）
  • 偏差发现时机晚（人工注意到时往往已不可逆）
  • QA 偏差调查从手工 30-90 天压到草稿 5-15 天
  • 重复偏差自动识别避免漏看
边界 / 凯莱英要做的事
  • 历史偏差标注库（6-12 月由资深 QA 配合做）
  • 反应釜 DCS 数据齐整（缺 tag 要补传感器）
  • 第一阶段定位"决策辅助"，不进 GMP 控制回路
  • 模型对从未见过的"新偏差"召回率有限

② RMS → 工艺配方 / MBR 版本管理与变更控制

优先级 ★★ 与 QMS 联动后做

半导体配方有几十到上千个参数，每个变更都要审批、留痕。智现未来 RMS 是这套治理的成熟系统。 CDMO 对应的是 MBR（Master Batch Record） + SOP + CPP/CQA 表。

输入
• 研发工艺包（CPP/CQA、SOP、设备清单）
• Change Control 申请
• 客户工艺变更指令
• 历史配方版本库
AI 处理
• 版本树管理 + diff 对比
• 变更影响分析（"改这个参数会影响哪些 CQA"）
• 与历史成功批次相似度评估
• 自动审批路由建议
输出
• 电子化的工艺配方（与 MES 对接执行）
• 变更审批工单
• 跨厂区配方一致性检查
• 监管核查应答材料
解决什么
  • 工艺包仍以 Excel/Word 流转、版本混乱
  • 客户工艺变更追溯困难（监管核查痛点）
  • 跨厂区（天津/敦化/吉林）配方不一致
边界
  • 必须过 GAMP 5 类别 4 验证 + 21 CFR Part 11
  • 凯莱英已有 QMS 系统，要避免重复
  • 建议作为 QMS 的"工艺配方子模块"集成而非独立部署

③ APC → 连续流反应 / 结晶过程的先进控制

优先级 ★★ 价值高但难度最大

在半导体里 APC 是闭环：AI 模型根据实时传感器读数自动调整工艺参数（如等离子功率），保持产品质量在目标范围。 在 CDMO 里对应"模型预测控制 (MPC) + 在线 PAT 软测量" — Quality by Design (QbD) 的最高形态。

输入
• DCS 实时数据
• 在线 PAT 光谱（IR/拉曼/UV）
• 工艺机理模型（动力学/传热）
• 当前 CQA 目标
AI 处理
• 软测量：从光谱实时算 CQA（不等离线 HPLC 24h）
• MPC：滚动预测 + 优化未来 30 min 参数轨迹
• 自适应：每批数据反馈优化模型
输出
• 软测量值实时显示
• 控制建议（人工确认后执行）
• 第二阶段：直接闭环控制（如自动调加料速度）
解决什么
  • 不同批次原料质量差异导致结果不一致
  • 收率波动大、杂质控制不稳定
  • 放行从天 / 周压到小时（叠加 RTRT）
边界 / 关键风险
  • 直接闭环控制涉及 GMP / CSV 验证最严
  • 第一阶段必须先用"建议模式"（人工确认后执行）
  • 需 12-18 月铺垫

④ 技术转移 / Golden Path → R&D 到生产的工艺移植加速

优先级 ★★★ CDMO 业务核心

半导体里 WRA + Golden Path 推荐：根据历史成功 wafer 的工艺路径，给新产品推荐最佳生产路径。 CDMO 对应：研发到中试到商业化的工艺包移植 + 设备等效性比对 + 黄金批次推荐。 这一项对 CDMO 业务的杠杆最大 — 缩短 NPI 时间 = 提前确认收入 + 客户复购。

输入
• 研发实验数据（小试/中试）
• 设备能力库（不同反应釜的搅拌/传热）
• 商业化车间设备清单
• 历史相似项目放大数据
AI 处理
• 设备等效性比对（雷诺数、传热系数）
• 历史项目相似度检索
• 工艺参数自动外推
• 放大风险识别
输出
• 商业化车间工艺包草案
• 放大风险清单
• 设备改造建议
• 同类历史项目偏差档案链接
解决什么
  • NPI 时间长（参考 BMS NPI −42%）
  • 首批成功率低、客户交付延期
  • 工艺包不完整、隐性知识丢失
边界 / 凯莱英要做的事
  • 需要凯莱英历史项目数据沉淀（数百个项目）
  • 设备能力库要标准化（搅拌雷诺数等参数）
  • 需 R&D 部门 + 生产部门 KPI 对齐配合

⑤ "灵犀" 问答模型 → QA 偏差 Copilot + SOP 助手 + 监管文档生成

优先级 ★★★ FDA CSA / EU Annex 22 已通

智现未来"灵犀"是半导体专属 LLM。在凯莱英要做的是制药专属 LLM — 基于凯莱英历史偏差库 + SOP + MBR + 工艺包向量化， 用 RAG 给 QA 工程师做偏差调查 / CAPA 拟稿 / 历史相似偏差检索。 AI 不替代签字，但把"找历史、写草稿、填模板"80% 的体力活省下来。

输入
• 当前偏差描述
• 该批次 DCS 实时数据
• 历史偏差库（向量化）
• SOP / MBR / 工艺包知识库
AI 处理
• RAG 检索 Top-K 相似偏差
• LLM 综合生成根因建议
• 根据 SOP / CAPA 模板拟稿
• 标出所有引用源
输出
• 偏差调查初稿
• CAPA 模板（已填关键字段）
• 同类历史偏差关联链接
• 引用源文档 + 条款
解决什么
  • 偏差关闭周期从 30-90 天压到 5-15 天
  • 批审核工时 −50%（行业基线）
  • PQR / 年度报告自动化（Sanofi 案例 −70%）
凯莱英要做的事
  • "灵犀"在制药语料上继续训练（凯莱英语料 + 公开制药文献）
  • 历史偏差库电子化 + 结构化标注
  • 合规：AI 输出必须可追溯到原始数据
  • 客户级数据隔离（见 PART 06）

⑥ 预测性维护 → 关键设备健康监测

优先级 ★ 凯莱英已有 DH1 项目推进

智现未来的 PdM 跟凯莱英 DH1 项目场景一致（冰机 / 空压机 / 离心泵）。 这一项不建议作为独立 PoC，而是看智现未来在 DH1 项目里的算法 / 经验能不能复用， 或者作为现有 PdM 供应商的备选。

凯莱英应对： 让智现未来与现有 PdM 供应商在同一台测试设备上跑对比，但不在本次 PoC 范围内开新项目。

⑦ Intelligence Hub → ⚠️ 平台底座 — 慎重

优先级 0 — 不建议

智现未来想推 Intelligence Hub 作为"数据底座 + AI 平台"。 这是这次合作里最大的"陷阱"。凯莱英在《数智化立项规划》Step 3 已经明确平台路线是 艾默生 IP.21 + Inmation。Intelligence Hub 跟这个平台直接冲突。

正确姿态：让智现未来的产品（FDC/RMS/APC/Q&A 等）作为应用层跑在艾默生平台上， Intelligence Hub 不进入凯莱英技术栈。这是平台层选型的红线。

PART 05 · 实时 Demo

FDC 跑在凯莱英连续流氢化反应上是什么样的

关键观察 1 · 多变量异常的本质

PART 07 · 数据安全 & 客户版权隔离

CDMO 业务命脉 — 不同客户的经验不能互通，AI 也不能

凯莱英给客户 A 做了一个反应工艺，从中积累了"催化剂 X 在 80℃ 这种条件下副产物 Y 高"的经验。 这条经验能不能用在客户 B 的项目上？— 法律和商业道德都不允许直接用。 但 AI 模型天然喜欢"跨客户学经验"，这是 CDMO 用 AI 最大的伦理 + 法律风险。本部分给出三层隔离方案。

三层隔离的具体实现

隔离层 实现方式 解决的风险 合同 / 流程支持
L1 · 物理 / 逻辑数据隔离 • 每个客户独立数据库 schema 或独立集群
• 客户访问严格按"项目权限"过滤
• 审计日志追到"用户 × 客户 × 操作" 		"原始数据不出客户域" 客户合同明确数据归属；ISO 27001 + Part 11 审计
L2 · 模型 / 参数隔离 • 客户专属微调模型不混用
• 联邦学习 / 差分隐私训练
• 共享层仅是通用底层算法（如 PCA / Transformer 架构本身） 		"模型参数不暴露客户数据细节" 合同写入"AI 模型训练许可" + "不得对外提供训练后模型"
L3 · 经验 / 知识沉淀脱敏 • 设"知识沉淀脱敏委员会"评议每条经验是否可外传
• 可跨客户共享：方法论 / SOP 模板 / 设备参数库（不含工艺细节）
• 不能共享：CPP 数值 / 杂质谱 / 催化剂体系 / 产物结构 		"经验抽象可共享、具体细节不可" 客户合同"脱敏经验沉淀许可"；IP 影响评估流程
关键风险 1 · 联邦学习不是万能

联邦学习理论可让"数据不出客户域、模型参数互通"。但模型参数本身可能反推出训练数据特征（model inversion attack）。 必须叠加差分隐私 + 严格审计。

关键风险 2 · 智现未来现场没回答这个

现场我们提出客户数据隔离问题，对方未给出明确方案。 这是 PoC 启动前必须落实的硬指标，应作为合同附件。

关键参考 · 半导体 Foundry 已有成熟方案

台积电 / 三星给数百家 IC 设计公司代工，半导体 Foundry 客户数据隔离方案是行业最严的之一。 智现未来在这一块的经验可以直接迁移 — 但需要他们主动给方案。

PART 11 · 重点决策 4 件事

需要管理层定的事

① 智现未来 PoC 范围与姿态

在 7 个产品中，仅启动方向 A（FDC）+ 方向 B（技术转移）双方向 PoC； Intelligence Hub 明确不进入凯莱英技术栈； 合同写明"应用层供应商角色"。 PoC 周期 6-9 月，投入封顶，KPI 写入合同。

② 基础设施立项

启动 PART 06 列出的 A/B/C 三类基础设施建设。 即使最终不选智现未来，这些也是所有 AI 战略的共同前置。 D 类（GPU 算力）按供应商需求分阶段投。 基础设施立项由 CIMT 牵头，工程 + IT + 财务联合评审。

③ 数据隔离专项

立即立项"AI 项目客户数据隔离专项"，3 个月内出方案： ① L1 物理/逻辑隔离架构 ② L2 联邦学习 + 差分隐私技术方案 ③ L3 知识沉淀脱敏委员会成立。 所有 AI 供应商合同的强制附件，包括智现未来。

④ 多供应商并行评估

在智现未来 PoC 期间，同步评估华为云盘古制药、Aizon、Mareana 至少 1 家。 每个核心 AI 方向（A/B/C/D/G）配 1-2 家备选供应商， 避免单点绑定。形成"凯莱英 AI 供应商组合"。

⑤ 给智现未来的"反向需求规格书"
