# 生产管理 AI 表格化方案（订单 → 项目 → 执行 → 延误预警 → 排产）

v0.3 简化版 ｜ 2026-11-09 ｜ 范围：先选一个厂区试点，表结构按全厂区设计

> 一句话：只有 5 张表需要人填，订单从其他部门同步；原来 9 个 Excel 模板都变成"批次"表上的视图，统计和预警自动生成。

## 一、现有模板理解

### 1.1 模板清单

| 模板 | 实际用途 | 一行代表什么 | 关键字段与计算 |
|---|---|---|---|
| 生产计划模板（V1/V2、设备需求信息、批次时间、生产计划说明） | 项目排产方案，需逐级审批 | 项目×步骤×批次×设备 | 投料量/产量、设备与体积、批次起止、客户交期/内部交期、版本与延误原因 |
| 单元操作时间（含物料版） | 每步工艺的操作清单和标准工时 | 项目×步骤，最多 61 个操作横向排开 | 标准时间、设备编号、物料/用量、主原料质量比、分析方法、送样数 |
| 月计划上传 / 各厂区月生产任务通告 | 月度任务承诺，导入 smart BI | 月×批次，可按比例拆到车间 | 计件批次 = 实际批次 × 标准系数；目标周期、三废、风险、月末是否完成 |
| 周计划上传 / 周计划模板 | 周执行计划 + 延误登记 + 回顾 | 周×批次 | 周计划/实际起止、每日进展、延误（原因/时长/责任人/是否解决）、投入/结束/运行完成率 |
| 生产日报 | 批次执行看板 | 批次 | V1 计划、最新计划、实际三套时间；开始延误、周期延误；产量、收率 |
| 项目生产成本核算 | 项目成本 | 项目×步骤（按月拆占用天数） | 成本 = 单位成本（美元/天·m³）× 周期 × 反应釜体积 |
| 延误原因分类（周计划模板内） | 字典 | 一类原因 | 共 26 类 |
| 生产看板流程图（Visio） | 现行流程 | — | 基础信息 → 文员导入 → 月/周/日报；周计划同步实际时间到月计划和日报；延误信息经钉钉、邮件推送 |

### 1.2 现状的主要问题

- **同一批次信息重复抄写 4–5 次**：项目号、步骤、批次出现在 7 张表；计划起止在 4 张表；实际起止在 4 张表；车间、生产经理在 5 张表。
- **写法不统一**：批次有"4/1""04/08（40%）""2&3/2""1n2"等写法；步骤有"Step1""step1""1"混用。模板里已经多次提醒"步骤不要出现 STEP"，说明这个问题一直存在。
- **单元操作时间是宽表**：一行一个步骤、操作向右排到 61 列，无法统计，也无法关联设备。
- **延误信息分散**：周计划、日报、未完成批次分析三处各记一份，原因分类只在周计划里有。
- **没有订单层**：客户交期只散落在生产计划和成本表里，无法从订单角度看交付风险。
- **成本靠手工按月拆分占用天数**。

## 二、简化设计思路

### 2.1 三条原则

- **只有 5 张表需要人填，加 1 张订单同步表**。订单数据由其他部门的 AI 表格同步过来，我们不手填。
- **原模板不再单独建表，改成批次表上的视图**。日报、周计划、月计划、未完成分析，本质上是同一批数据换个筛选条件和列顺序，用视图就能生成，并且可以直接导出 Excel。
- **统计分析单独看**。车间统计和项目统计做成独立的统计视图，另配 3 个仪表盘，都是自动汇总，不需要人录入。

### 2.2 表结构（6 张）

```
订单同步（其他部门同步，只读）
   │ 关联订单
   ▼
项目 ──────────────┐
   │ 所属项目      │ 所属项目
   ▼               ▼
工艺步骤 ──所属步骤──▶ 批次（中枢）◀──主车间── 车间
                     ▲
                     │ 批次
                现场记录（进展 + 延误）──原因分类──▶ 延误原因
```

| 表 | 一行代表 | 谁填 | 何时填 | 作用 |
|---|---|---|---|---|
| 车间 | 一个车间 | 生产文员 | 一次性 | 基础数据；车间统计也放在这张表 |
| 延误原因 | 一类原因 | 生产文员 | 一次性导入 | 26 类字典 |
| 订单同步 | 一张订单 | 不填，自动同步 | 每天同步 | 客户交期、数量、状态 |
| 项目 | 一个项目（一次生产） | 项目组 | 立项时 | 项目信息；项目统计也放在这张表 |
| 工艺步骤 | 项目的一个步骤 | 项目组 + 生产部 | 排产前 | 标准系数、标准周期、排产参数 |
| 批次 | 一个批次 | 计划员排产；车间更新执行情况 | 排产时建；执行中每天更新 | 中枢：计划、实际、预警；原模板都从这里生成 |
| 现场记录 | 一条进展或一次延误 | 车间 | 每天、发生即填 | 合并原来的进展日志和延误记录 |

### 2.3 编码规则（迁移前统一）

| 对象 | 规则 | 示例 |
|---|---|---|
| 项目号 | 类别 + 编号 - 生产次数 | CPo127075-04 |
| 步骤号 | 只写数字；合并步骤用"&" | 4、2&3 |
| 步骤 ID | 项目号-S步骤号 | CPo127075-04-S4 |
| 批次号 | 整数，不写"Batch" | 1、2、3 |
| 批次 ID | 项目号-S步骤号-B两位批次号 | CPo127075-04-S4-B01 |
| 车间编码 | 厂区-车间 | DH1-二车间 |

一个批次跨两个车间按比例生产时，一期只登记主车间，在"拆分说明"里写明比例（例如"二车间40%/六车间60%"），按比例计件放到二期。

### 2.4 订单数据怎么引用

AI 表格的关联和引用只能在同一个 Base 内使用，不能直接引用其他部门的 Base。做法是在我们的 Base 里放一张"订单同步"表，由对方的数据定期同步过来，我们只读不填。

| 方式 | 做法 | 前提 | 评价 |
|---|---|---|---|
| A. AI 表格自带同步 | 在我们的 Base 新建同步表，数据源选对方的 AI 表格 | 对方给我们至少"可阅读"权限；界面里有这个功能（需核实，命令行目前只支持同步 OA 审批数据） | 首选 |
| B. 对方建自动化 | 对方订单新增或修改时，自动写入我们的订单同步表 | 对方愿意配置；工作流支持跨 Base 写入（需核实） | 实时，但依赖对方 |
| C. 千问 skill 定时同步 | 每天读取对方的表，按订单号写入或更新我们的表 | `dws` 的 AI 表格权限开放 + 对方给阅读权限 | 可控，依赖权限 |
| D. 手工导入 | 对方定期导出 Excel，我们导入覆盖 | 无 | 兜底 |

**现在怎么做**：先建一张"订单同步"占位表，主字段为订单号，再加客户交期、数量、状态等几个常用字段，项目表通过订单号关联它。拿到对方的字段清单后：
- 如果用方式 B、C、D：把对方字段映射到这张表的字段上，表结构不用改；
- 如果用方式 A：系统会生成一张新的同步表，需要把项目表的"关联订单"改为关联到新表，再删除占位表。

**需要向对方确认**：能否共享 Base 并给我们可阅读权限；订单表的字段清单；订单号是否唯一。

## 三、怎么用

### 3.1 填写分工（哪些字段需要人填）

每张录入表都有一个"✏️"开头的填写视图，只显示要人填的字段。每个要填的字段，在字段描述里都写明了填写人。其余字段都是自动计算的，填写视图里看不到。

| 表 | 填写人 | 要填的字段 | 自动生成的字段（不用填） |
|---|---|---|---|
| 车间 | 生产文员（一次性） | 车间编码、厂区、车间名称、生产经理 | 车间统计的全部字段 |
| 项目 | 项目组 | 项目号、项目类型、项目类别、GMP级别、项目主管、Coreteam、Coreteam负责人、生产配对负责人、主生产厂区、项目状态、关联订单 | 交期、批次数、完成进度、预计完成日、交付风险、累计延误 |
| 工艺步骤 | 项目组 + 生产部 | 步骤ID、所属项目、步骤号、是否终产品、批次数、单批投料量、单批产量、预期收率、标准系数、标准批次周期、首批计划开始、批次投料间隔、放行等待、上游步骤、敏感化学品、是否三废、主反应釜规格、风险点、规避措施 | 首批/末批建议结束、最早可开始、排产检查 |
| 批次：排产 | 生产计划员 | 批次ID、所属项目、所属步骤、主车间、批次号、计划版本、V1计划开始/结束、最新计划开始/结束、计划变更原因、拆分说明 | 建议计划起止、各类延误天数、预警等级、本周/本月标记 |
| 批次：执行 | 车间 | 状态、当前进展、进展说明、实际开始、实际结束、实际产量；月底补三废数量 | 实际周期、实际收率、周期延误 |
| 现场记录 | 车间 | 批次、记录类型（进展/延误）、发生时间、当前工序、记录说明；延误时再填延误时长、原因分类、负责人、责任人、是否解决、解决措施 | AI建议分类、大类、项目号、车间 |

**最简单的日常操作**：
- 计划员：在"✏️ 排产录入"视图排产，参考系统给出的建议起止时间。
- 车间：每天在"✏️ 车间更新"视图改状态和实际时间；有进展或延误，用"✏️ 现场填报"表单登记一条。
- 管理人员：只看"📋"开头的报表视图和"📈"开头的统计视图。

### 3.2 原模板在哪里看

| 原模板 | 现在的位置 | 说明 |
|---|---|---|
| 生产日报 | 批次 → 📋 生产日报 | 列顺序与原模板一致：V1 计划、最新计划、实际、开始延误、当前进展、周期延误、产量、收率 |
| 周计划 / 周计划上传 | 批次 → 📋 本周计划 | 筛选"本周涉及=1"，列顺序同周计划上传模板，可直接导出 Excel |

| 下周计划 | 批次 → 📋 下周计划 | 筛选"下周涉及=1"，每周六自动推送 |
| 月计划上传 / 月生产任务 | 批次 → 📋 本月计划 | 筛选"本月涉及=1"，含标准系数、计件批次和三废字段 |

| 延误统计 | 现场记录 → 📋 未解决延误；仪表盘"延误分析" | 原周计划模板里的延误部分 |

### 3.4 预警和自动化（一期 3 个，另有 1 个可选）

| # | 名称 | 触发 | 动作 |
|---|---|---|---|
| A1 | 每日批次预警 | 每天 08:30 | 把红色、黄色预警批次发给对应的生产经理和项目主管 |
| A2 | 延误通知 | 现场记录新增一条"延误" | 通知负责人、责任人 |
| A3 | 周六推送 | 每周六 09:00 | 推送本周未完成批次和下周计划批次 |
| A4（可选） | 进展同步 | 现场记录新增一条"进展" | 把当前工序和说明写回批次。系统不支持时，车间直接在"✏️ 车间更新"里改 |

预警规则：
- 🔴 红：已过最新计划结束日仍未完成，或开始延误 ≥ 2 天，或周期超出 ≥ 2 天；
- 🟡 黄：开始延误 1 天、周期超出 1 天，或有未解决的延误；
- 🟢 绿：其他；
- ⚪ 关闭：已完成或已取消。

### 3.5 排产（一期）

- 每批建议开始 = 首批计划开始 +（批次号 − 1）× 批次投料间隔；建议结束 = 建议开始 + 标准批次周期。
- 下游步骤的首批最早可开始 = 上游首批建议结束 + 放行等待；排早了会标"⚠ 早于上游放行"。
- 计划员参考建议时间，确认后填入"最新计划开始/结束"。

### 3.6 放到二期的内容

单元操作工时（MOR 项目可复用）、设备台账与设备占用冲突检查、成本核算、按比例拆分车间计件、周/月计划快照（如需考核周初承诺）。

### 3.7 上线节奏（6 周）

| 周 | 内容 | 产出 |
|---|---|---|
| 1 | 统一编码；整理试点厂区车间；向订单部门申请共享 | 基础数据、订单权限 |
| 2 | 按提示词建 Base；导入在制项目、步骤、批次 | 可用的 Base |
| 3–4 | 车间日常更新和现场填报，与 Excel 并行 | 报表视图可替代原模板 |
| 4 | 预警自动化和仪表盘上线 | 每日预警 |
| 5 | 接入订单同步 | 交付风险可用 |
| 6 | 复盘，停用原 Excel 模板 | 一期验收 |

### 3.8 我的判断 / 依据 / 不确定性

- **我的判断**：5 张录入表加视图化报表，能覆盖原来 9 个模板的日常用途，学习成本最低。
- **我的依据**：原模板之间主要是"同一批数据换筛选和列顺序"，正好是视图擅长的；真正需要人录入的只有计划、执行和延误三类信息。
- **我的不确定性（需核实）**：
  - 跨 Base 同步订单的具体入口和权限要求；
  - 公式中 WEEKDAY 函数是否可用（"本周"标记依赖它）；
  - 自动化能否"更新关联记录"（A4 依赖）、能否给"引用"出来的人员字段发消息（A1 依赖）；
  - `dws` 的 AI 表格权限仍被组织策略禁止，开放后千问才能代建和读取数据。

## 四、AI 表格搭建提示词（v3 简化版）

### 4.1 使用方法

1. 新建空白 AI 表格 Base，命名为"生产管理（试点）"，打开 AI 助手。
2. **按顺序逐段发送**，共 12 段（0、1、1B、2 到 10）。每段发完，按"验收"检查，通过后再发下一段。
3. AI 助手一次处理不完时，把一段拆开，**一次只发一张表**。
4. 弹出"覆盖已有字段""修改字段类型""不可撤销"之类的确认框，**一律点取消**。

### 4.2 已踩过的坑（本版已规避）

| 问题 | 原因 | 本版做法 |
|---|---|---|
| 关联字段被覆盖成"关联引用" | 旧提示词用"｜"分隔，AI 把关联字段名当成了要新建的字段 | 每条指令写成"新建字段=…；使用的关联字段=…"，每段开头重复"只新增、不覆盖" |
| 字段名显示乱码 | "$"被当成数学公式符号 | 字段名只用中文、字母、数字和半角括号 |
| 引用字段不能被再次引用或求和 | 系统限制 | 需要跨表汇总的，先建以"值"或"标记"结尾的公式字段，再引用它 |
| 依赖字段不存在导致失败 | 一段里混建了互相依赖的字段 | 按"关联 → 引用 → 公式 → 引用 → 公式"分轮建 |
| 关联字段和表同名，AI 分不清 | 例如字段叫"项目"，表也叫"项目" | 关联字段带前缀（所属项目、所属步骤、主车间）；反向字段建好后立即改成指定名称 |

### 4.3 搭建顺序

| 段 | 内容 |
|---|---|
| 0 | 规则 |
| 1 | 2 张基础表：车间、延误原因 |
| 1B | 录入 26 条延误原因（也可导入种子 Excel） |
| 2 | 5 张业务表：订单同步、项目、工艺步骤、批次、现场记录 |
| 3 | 8 个关联字段（7 个双向 + 1 个单向） |
| 4 | 引用第一轮（22 个） |
| 5 | 公式第一轮（31 个，含本周/本月标记） |
| 6 | 引用第二轮（17 个，含车间统计、项目统计） |
| 7 | 公式第二轮（8 个，含预警、完成率） |
| 8 | AI 字段（2 个） |
| 9 | 视图（填写视图、报表视图、统计视图） |
