# 生产管理 AI 表格化方案（订单 → 项目 → 执行 → 延误预警 → 排产）

v0.1 ｜ 2026-11-09 ｜ 范围：先选一个厂区试点，表结构按全厂区设计

> 一句话：以"批次"为中枢，把 9 个 Excel 模板合并成一个钉钉 AI 表格 Base。基础数据只录一次；计划、实际和延误自动流转；统计和预警自动生成。

## 一、现有模板理解

### 1.1 模板清单

| 模板 | 实际用途 | 一行代表什么 | 关键字段与计算 |
|---|---|---|---|
| 生产计划模板（V1/V2、设备需求信息、批次时间、生产计划说明） | 项目排产方案，需逐级审批 | 项目×步骤×批次×设备 | 投料量/产量、设备与体积、批次起止、客户交期/内部交期、版本与延误原因 |
| 单元操作时间（含物料版） | 每步工艺的操作清单和标准工时 | 项目×步骤，最多 61 个操作横向排开 | 标准时间、设备编号、物料/用量、主原料质量比、分析方法、送样数 |
| 月计划上传 / 各厂区月生产任务通告 | 月度任务承诺，导入 smart BI | 月×批次，可按比例拆到车间 | 计件批次 = 实际批次 × 标准系数；目标周期、三废、风险、月末是否完成 |
| 周计划上传 / 周计划模板 | 周执行计划 + 延误登记 + 回顾 | 周×批次 | 周计划/实际起止、每日进展、延误（原因/时长/责任人/是否解决）、投入/结束/运行完成率 |
| 生产日报 | 批次执行看板 | 批次 | V1 计划、最新计划、实际三套时间；开始延误、周期延误；产量、收率 |
| 项目生产成本核算 | 项目成本 | 项目×步骤（按月拆占用天数） | 成本 = 单位成本（美元/天·m³）× 周期 × 反应釜体积 |
| 延误原因分类（周计划模板内） | 字典 | 一类原因 | 共 26 类 |
| 生产看板流程图（Visio） | 现行流程 | — | 基础信息 → 文员导入 → 月/周/日报；周计划同步实际时间到月计划和日报；延误信息经钉钉、邮件推送 |

### 1.2 现状的主要问题

- **同一批次信息重复抄写 4–5 次**：项目号、步骤、批次出现在 7 张表；计划起止在 4 张表；实际起止在 4 张表；车间、生产经理在 5 张表。
- **写法不统一**：批次有"4/1""04/08（40%）""2&3/2""1n2"等写法；步骤有"Step1""step1""1"混用。模板里已经多次提醒"步骤不要出现 STEP"，说明这个问题一直存在。
- **单元操作时间是宽表**：一行一个步骤、操作向右排到 61 列，无法统计，也无法关联设备。
- **延误信息分散**：周计划、日报、未完成批次分析三处各记一份，原因分类只在周计划里有。
- **没有订单层**：客户交期只散落在生产计划和成本表里，无法从订单角度看交付风险。
- **成本靠手工按月拆分占用天数**。

## 二、数据打通设计

### 2.1 核心思路

- **一个中枢**：批次主表。一行 = 项目×步骤×批次，承载三套时间（V1 计划、最新计划、实际）和状态。
- **基础数据只录一次**：项目、步骤、车间、设备、Coreteam、延误原因分类，其他表一律通过"关联 + 引用"取值，不再手抄。
- **月计划、周计划改为"快照"**：从批次主表自动生成当期记录，冻结当期的计划时间；实际时间引用批次主表，自动同步。这对应 Visio 中"周计划同步实际时间、进展"。
- **延误单独成表**：一条延误一行，挂到批次上，再汇总到批次、周、月、项目。

### 2.2 编码规则（迁移前必须先统一）

| 对象 | 规则 | 示例 |
|---|---|---|
| 项目号 | 沿用现有规则：类别 + 编号 - 生产次数 | CPo127075-04 |
| 步骤号 | 只写数字；合并步骤用"&" | 4、2&3 |
| 步骤 ID | 项目号-S步骤号 | CPo127075-04-S4 |
| 批次号 | 整数，不写"Batch" | 1、2、3 |
| 批次 ID | 项目号-S步骤号-B两位批次号 | CPo127075-04-S4-B01 |
| 车间编码 | 厂区-车间 | DH1-二车间 |
| 设备编号 | 以设备台账为准 | — |
| 月份 / 周次 | YYYY-MM / YYYY-Www | 2026-11 / 2026-W46 |

一个批次按比例拆到两个车间时（原"04/08（40%）"写法），批次 ID 不变，在月计划中拆成两行，分别写车间和"实际批次"（0.4、0.6）。

| 设备、规格容积 | 设备台账 | 单元操作、设备需求、设备占用 | 生产计划、单元操作、月计划 |

### 3.2 填写顺序

```
① 基础数据   车间、设备、Coreteam、延误原因、成本参数（生产文员，一次性）
      ↓
② 订单       商务/项目经理录入订单与交期
      ↓
③ 项目       项目组建项目，关联订单和 Coreteam
      ↓
④ 工艺准备   工艺步骤 → 单元操作（标准工时）→ 设备需求（项目组+生产部）
      ↓
⑤ 排产 V1    生产计划员填"首批开始、投料间隔"，系统给出每批建议起止
             → 人工确认写入"最新计划" → 审批后复制为 V1 并锁定
      ↓
⑥ 月计划     每月 25 日自动生成下月快照，生产部确认拆分比例和风险
⑦ 周计划     每周五自动生成下周快照，周六推送项目人
      ↓
⑧ 执行       车间每天写进展日志，系统同步批次的实际起止和状态
⑨ 延误       发生即登记，自动推送负责人；每日统计
      ↓
⑩ 回顾       周回顾、月末回顾自动算完成率；AI 生成周/月总结
⑪ 成本       步骤完成后自动计算实际成本
```

### 3.3 各表说明

| 表 | 功能 | 能看到什么 | 统计 / 计算 |
|---|---|---|---|
| 订单 | 订单、交期、交付状态 | 每张订单的预计完成日和交付风险 | 距交期天数；交付风险（红/黄/绿） |
| 项目 | 项目主数据，连接订单和生产 | 项目的批次数、完成进度、预计完成日、累计延误 | 完成进度 = 已完成批次 ÷ 批次数；计划/实际成本合计 |
| 工艺步骤 | 步骤参数、排产输入、成本 | 标准批次周期、末批建议结束、是否早于上游放行 | 标准周期 =（工时合计 ÷ 24）×（1 + 缓冲系数），向上取整；计划/实际成本 |
| 单元操作 | 替代原宽表，一个操作一行 | 每步的操作清单、工时、设备、物料、送样 | 工时合计汇总到步骤 |
| 设备需求 | 每步需要的设备和体积 | 设备装载率 | 装载率 = 最大体积 ÷ 设备容积，超过 90% 标红 |
| 批次主表 | 中枢：三套时间 + 状态 + 预警 | 日报视图、甘特图、预警清单 | 建议起止、开始延误、实际周期、周期延误、较 V1 延误、实际收率、预警等级 |
| 批次进展日志 | 替代日报中的"每日进展" | 每批次的进展时间线 | 自动同步批次的当前进展和实际起止 |
| 延误记录 | 所有延误的唯一登记处 | 未解决延误、延误明细 | 延误天数；按原因、大类、车间、coreteam 汇总 |
| 月计划 | 月度任务承诺 | 每月任务清单、完成情况 | 计件批次 = 实际批次 × 标准系数；月末是否完成 |
| 周计划 | 周执行计划 | 下周计划、本周未完成批次 | 计划/实际投入、结束、运行；开始延误、结束延误 |
| 设备占用 | 排产冲突检查 | 按设备分组的甘特图 | 占用天数；冲突标记 |

### 3.6 AI 能力

- **AI 字段**：
  - 延误记录"AI 建议分类"：根据延误描述，从 26 类中给出建议，人工确认后写入正式分类；
  - 批次主表"AI 风险提示"：根据延误、进展和预警情况，给出一句话风险判断；
  - 项目"AI 状态摘要"：一句话总结项目进度与主要问题。
- **汇总分析**：每周一、每月 1 日，用千问的文件速读与数据分析 skill（doc-insight）读取 AI 表格数据，生成周报、月报。前提是 `dws` 的 AI 表格权限已开放。

### 3.7 排产（一期：规则推算 + 甘特 + 冲突预警）

- **批次建议时间**：
  - 建议开始 = 首批计划开始 +（批次号 − 1）× 投料间隔；
  - 建议结束 = 建议开始 + 标准批次周期。
  - 生产计划员确认后写入"最新计划"。
- **上下游衔接**：下游首批最早可开始 = 上游首批建议结束 + 放行等待天数；早于这个日期时标"⚠ 早于上游放行"。
- **设备冲突**：AI 表格的公式和查找引用都不能做"同一设备、时间重叠"的判断。一期采用两种方式：
  1. 设备占用表用甘特视图按设备分组，目视检查；
  2. 每天由自动化或千问 skill 扫描一次，写入"冲突标记"（自动化能否做到需核实，做不到则用 skill）。
- **二期**：基于设备占用和工时的自动排产建议，需要外部脚本支持。

### 3.9 我的判断 / 依据 / 不确定性

- **我的判断**：先跑通"批次主表 → 周计划 → 进展日志 → 延误预警"这条线，价值最直接；订单、成本、排产随后补上。
- **我的依据**：Visio 流程中周计划是枢纽；延误数据最全，管理诉求最强。
- **我的不确定性（需核实）**：
  - 引用字段的再引用：搭建中已确认"引用字段不能作为求和来源"，已用"中转公式字段"解决（如批次主表的「延误合计值(h)」）；"原值"方式的再引用是否稳定，仍需在有数据后核对；
  - 字段名中不要使用"$"，钉钉会把它当作公式符号导致显示错乱，金额单位统一写"美元"；
